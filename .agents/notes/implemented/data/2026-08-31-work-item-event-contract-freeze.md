# Agent Note: Work Item v1 领域事件冻结与接收者引用边界

Status: implemented

## Problem

Work Item、Update 与 Relation 已分别交付生产者、Outbox Schema 和 Activity 消费者，但缺少一个可审查的冻结清单和相对 PR 基线的兼容门禁。仅校验当前 Schema 与当前样例能够同时通过，无法阻止删除事件、改变聚合语义、收紧既有字段或让历史合法样例失效。通知接收者若直接从标题、正文或治理理由推断，跨项目关系若复用完整双端事件展示，也会把业务内容或不可见端标识扩散到原授权范围之外。

## Decision

M2-23 以 `contracts/events/freeze/workitem-m2-v1.json` 冻结 14 类 Work Item 核心 v1 事件：Work Item 八类、Update 三类和 Relation 三类。Content 四类与 Attachment 两类继续受既有契约、Activity 和回归门禁保护，但不重复进入本清单。清单同时登记事件类型、版本、聚合、Schema、生产者、Activity 消费者、目标引用和接收者引用，生产者清单与 Activity v1 订阅必须和冻结集合持续对账。

同一 v1 只允许增加可选字段。事件名、版本、聚合类型、聚合版本约束、必填字段集合、既有字段定义和 `additionalProperties: false` 均不可改变，历史合法样例必须继续通过当前 Schema；破坏性演进必须新增 v2 并保留 v1。CI 从 PR 目标分支提交提取临时基线，不在仓库复制 Schema 快照；新增事件或新版本不阻塞既有 v1 检查。

即时接收者只把事件中的稳定引用当候选：`work_item_assigned` 使用 `assigneeUserId`，`work_item_update_published` 使用 `mentionedUserIds`，其余冻结事件不建立 M2-23 即时通知触发器。所有消费者在发送或展示前重新校验账号状态、当前 Project 权限和资源状态；标题、描述、备注、Update 正文、删除理由和状态处理说明都不是安全通知载荷。到期提醒由后续调度器读取当前事实，不从历史事件直接决定接收者。

跨项目 Relation 事件保留双端引用以支持可靠投影，但消费者必须按 left/right Project 分别建立端点投影；任一投影不得持久化或展示另一侧 Work Item ID。Activity 继续采用当前端点范围的双投影和实时查询授权，不把完整双端事件当成可直接展示的读模型。

## Alternatives considered

- 把当前 Schema 复制为一份永久 baseline：拒绝。重复快照会形成第二真源并增加同步噪声；PR 目标提交已经是准确的历史基线。
- 只运行 Schema 与样例合法性校验：拒绝。当前 Schema 和当前样例可以一起发生破坏性变化，无法保护既有消费者与历史合法载荷。
- 允许 v1 增加新的必填字段：拒绝。旧生产者和历史事件无法补齐新字段；这类演进必须使用 v2。
- 把标题或正文摘要直接作为通知载荷：拒绝。事件投递与通知展示之间可能发生失权、归档或账号停用，内容也可能超出接收者当前权限。
- 跨项目关系只发两条单端事件：拒绝。会改变已冻结的事件线形并增加生产者原子性负担；单端隐私由消费者投影边界封闭。

## Consequences

任何修改冻结 Schema 的 PR 都必须取得目标分支基线并通过兼容检查；新增可选字段时仍需补充当前合法/非法样例和生产者测试。删除 v1、改变约束或重解释聚合需要新版本、双版本消费迁移和显式退役决策。新增 Work Item 核心事件必须同步冻结清单、生产者审计、Activity 订阅与运行时 Outbox 覆盖，否则门禁失败。

通知和 Activity 消费者不能把“事件已投递”视为“当前可见”，必须在副作用发生前读取当前授权与资源事实。跨项目关系消费者承担双端隔离义务；若未来需要向一侧展示对端标识，必须另行建立经过双侧授权的查询或安全投影，不得放宽当前冻结清单的隐私声明。
