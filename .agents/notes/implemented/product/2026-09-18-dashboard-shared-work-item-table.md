# Agent Note: 仪表板下钻复用完整工作项表格

Status: implemented

## Problem

仅复用单元格仍会产生两套表格结构、分组、列偏好和操作入口，工作项页面的改进无法自然出现在图表下钻。分析弹窗需要在图表约束内提供原表格操作，且不得通过分页、子项展开或本地筛选绕开统计范围。

## Decision

本记录部分替代[仪表板保存恢复与展开视图](2026-09-18-dashboard-recovery-and-exploration.md)中“独立 25 条明细表、只复用单元格”的决定。其保存恢复、手动刷新、统一弹窗和原始耗时统计口径继续有效；旧记录保留上述独特职责，不归档。

[ProjectWorkItems](../../../../frontend/web-app/src/components/projects/ProjectWorkItems.vue) 是项目工作项页与仪表板共同使用的表格实现。项目页面只保留路由入口；嵌入模式沿用工具栏、字段编辑、详情、行菜单、子项、排序、分组与创建逻辑，并将图表固定在上部、滚动限制在下半表格区域，不携带项目导航。嵌入容器沿用原表格的行菜单留白与网格对齐，表格滚轮在边界允许传递给下半区的跨项目容器。跨项目下钻按项目分别实例化，以项目目录及权限为准，不强行合并各项目的字段选项。

通过 WorkItemTableSource 替换列表、分组选项和子项读取。服务端 `/me/dashboards/{id}/table/query` 先验证仪表板所有权、连接项目与当前可访问项目交集，再把全局筛选、组件筛选及图表分类/系列选择作为不可由表格筛选放宽的 scope，交给原工作项查询完成游标、排序、分组筛选和编辑快照。游标指纹包含图表 scope，不能跨选择重用；计时快照沿用原有版本失效机制。跨模块调用经过 WorkItemStatisticsQuery 公开端口。

表格根项展示保留命中子项的父项作为上下文，并明确标记。子项入口数量与展开结果都受图表 scope 约束。真实 subitemCount 保留给结构操作校验，范围内计数由 subitemCounts 单独提供，避免隐藏子项后错误开放转换操作。图表仍按每个原始事项统计，父项上下文不额外计入图表数量。表格内部筛选、分组沿用根项语义；子项跟随父项。行菜单置顶置底使用范围内的锚点，写入仍采用既有项目/父项顺序接口。

字段与结构修改继续走既有命令和权限检查。名称在嵌入模式启用严格版本检查，避免覆盖过期快照；完成后刷新图表和表格，不再匹配的事项移出。未完成的名称、字段、创建或讨论输入阻止关闭或切换分析范围。

初次嵌入沿用项目表格的列与分组偏好，此后按企业、用户、仪表板、组件和项目隔离持久化；嵌入查询状态不修改工作项页面路由。项目页面的既有偏好键保持兼容。

## Alternatives considered

- 继续维护独立下钻表并逐一复制操作：会持续产生样式、交互和权限分支，因此采用同一个表格实现。
- 在前端取得一页统计明细后过滤：无法正确处理分页、分组计数及未加载的子项，因此在服务端组合 scope。
- 直接挂载带项目导航的完整路由页面：弹窗会承担页面路由与全局滚动职责，因此抽出共享内容并提供嵌入上下文。
- 将所有项目合并成一张表或共用偏好：状态、类别、成员及权限可能不同，因此按项目展示与隔离。

## Consequences

没有数据库迁移或依赖变更。新增表格查询保留旧明细 API 兼容性。大范围跨项目展开会分别加载项目元数据和表格，成本随可见项目数增长。图表数值与包含父项上下文的根项行数不必相等。
