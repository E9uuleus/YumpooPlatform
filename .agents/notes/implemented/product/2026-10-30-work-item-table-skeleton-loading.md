# Agent Note: 工作项表格骨架加载

Status: implemented

## Problem

工作项表格首屏使用品牌加载遮罩和「正在加载…」文字，向下翻页在表格末尾显示「正在加载更多工作项…」，分组和看板的加载行也只有文字。遮罩盖住表格结构，文字所在行既不对齐真实列，也不提示接下来会出现什么；宽表格上居中的文字还可能落在可视区外。

## Decision

工作项表格、分组、子项表和看板的加载状态统一改为灰度骨架：灰块组成与表格同样的网格，一道高光从左到右扫过，加载结束即移除。骨架不显示文字，以 `role="status"` 和 `aria-label` 向读屏软件说明正在加载。

- `WorkItemTableSkeleton.vue` 按真实列宽、行高和固定列绘制骨架行，列宽与快速添加行同源。名称列和左侧固定列使用 sticky，横向滚动时与表格冻结区一致。各列按类型绘制不同形状：状态和优先级是满格色块，处理人是圆形，类别是胶囊，日期和时长是短条。
- 首屏在表头下显示 10 行骨架并隐藏快速添加。翻页时在已加载行之后、快速添加之前显示 3 行。分组加载行显示 2 行，计数未就绪时显示扫光胶囊。项目信息尚未返回时，用页头、工具栏和带表头的骨架代替整页品牌遮罩。
- 看板泳道用 `WorkItemKanbanSkeleton.vue` 的骨架卡片。子项表在 60px 空白区显示两条骨架。
- 扫光样式集中在 `workItemSkeleton.css`。它使用 `overflow: clip` 而不是 `hidden`，以免 sticky 单元格失去外层滚动容器。高光颜色从 `--yp-bg-raised` 混合而来，三主题通用。
- 新加载的表格行以 180ms 淡入，`animation-fill-mode: backwards` 不会盖过拖动源行等状态的透明度。
- 减少动态效果时只保留静态灰度框架。

扫光只在等待数据时运行，属于加载反馈，与[品牌加载遮罩](2026-09-14-brand-identity-and-loading.md)同类，不属于[非工作面氛围动效](2026-09-30-canvas-ambient-motion.md)所限制的持续装饰动画。其他页面的首次读取改用 `YpSkeleton`（见[视觉契约](2026-10-31-visual-contract.md)），已有数据时的刷新继续用品牌遮罩；页面级顶部进度条（[页面加载提示分工](2026-10-29-page-loading-progress.md)）与骨架并存。

## Alternatives considered

- 保留品牌遮罩，只把文字换成动画：仍然盖住表格结构，翻页和分组加载行也没法使用遮罩。
- 使用 `el-skeleton` 通用骨架块：不感知列宽、固定列和行高，无法与真实列对齐。
- 每个灰块各自做渐变动画：多块之间的高光不同步，宽表格上显得杂乱；改用一道覆盖整块骨架的高光。

## Consequences

新增内置列类型时，需要在 `WorkItemTableSkeleton.vue` 的 `shape()` 里登记灰块形状，否则按中等长度条形绘制。骨架依赖 `ProjectWorkItems.vue` 中的列宽与行高设置，调整表格固定列或行高时需同时检查骨架是否对齐。表格加载状态的单元测试只验证骨架存在且不出现加载文字，对齐与扫光效果需要在真实浏览器中检查。
