# Agent Note: 双向连接列与 Monday 式连接交互

Status: implemented

## Problem

连接列最初是单向的：来源项目维护连接列，目标项目只能在一列「被连接」汇总列里看到所有入站连接，既不能从目标侧关联或新建，也看不出连接来自哪一列。建列需要在 640px 对话框中先起列名再选项目；单元格弹层只能按标题搜索；连接卡片固定为只读的最小投影。用户要求参照 Monday 重做：点「+」立即出现新列并弹出连接引导，提示建立的是双向连接，列名取连接的项目名，单元格复用工作项颜色条，弹层可按字段筛选与勾选工作项并以「Add task」新建，已连接工作项能直接编辑字段且修改进入该工作项动态，同时移除「被连接」列。

## Decision

**始终双向，不新增持久化。** 每个连接列在其每个目标项目中呈现为一列反向列，列名取来源项目名，同一来源项目有多列时为「项目 · 列名」；它取代「被连接」汇总列。反向列不是新的列实体，而是从同一条 `work_item_connection` 推导：列目录的 `incomingColumns` 描述反向列（含来源项目生命周期与 `actorCanLinkExisting`），批量单元格新增 `incomingByColumn`，每列首批 50 条并给出列内完整计数；`/work-items/{id}/incoming-connections` 可按 `columnId` 分页。旧的 `incoming`、`incomingTotal` 保留为跨列兼容视图，由各列首批合并后取前 50 条，与原全局窗口等价，SQL 次数不变。反向列宽度与显隐使用 `connect-reverse:<columnId>` 键，位于本项目连接列之后；表头只提供隐藏，并以双向图标与提示说明来源列。

**两端都可维护。** 目标侧关联已有工作项复用 `linkWorkItemConnection`（对调两端 ID）；搜索与新建使用新增的 `reverse-connect-candidates`、`reverse-connect-create-options` 与 `reverse-connected-work-items`。反向操作要求操作人同时是两端项目 OWNER/MEMBER 且两端 ACTIVE，因此不构成跨项目投递：反向新建的根项建在连接列所在项目，连接 `origin` 记为 `LINKED`，不触发投递通知。解除连接仍只需任一端成员。权限边界见[连接投递与卡片可见性](../security/2026-09-30-connection-intake-and-card-visibility.md)。

**Monday 式建列。** 列中心选择「连接项目」后，表格在本项目连接列之后插入不落库的草稿列（占位单元格依次淡入），表头弹出两步设置弹层：引导页播放一次性 Canvas 连接插画（见 [Canvas 动效](2026-09-30-canvas-ambient-motion.md)），项目页提供最近使用、全部项目搜索与 20 个上限，并提示「将创建双向连接」。连接后以 `connectColumnAutoName` 生成列名：单个项目取项目名，多个用「、」连接，超过 40 字改为「首个项目 等 N 个项目」，与内置列和已有列冲突时追加序号；之后修改目标时，若列名仍等于旧目标的自动名则随之更新，否则保留手动名。表头支持双击或菜单内联重命名；关闭弹层即丢弃草稿列。新列以一次光带扫过和颜色条依次点亮呈现，减少动态效果时关闭。原添加/设置对话框与新建并关联对话框移除。

**单元格与选择弹层。** 单元格是带左侧圆角颜色条的盒子（共享 `workItemAccentBar.css`，颜色跟随所在行分组色），空值显示「–」，悬停出现加号，打开时显示单层焦点描边；窄列至少显示一个可截断的连接标签与 `+N`。「选择工作项」弹层打开即浏览，已连接项置顶，候选按状态分组并以状态色颜色条区分，勾选即关联、取消勾选即解除并提供撤销；搜索支持选择名称、处理人、状态、优先级、类别字段与按最近更新/名称排序，滚动加载下一页；输入标题后底部出现「＋ 新建工作项「标题」」行，可切换类别，一步新建并关联。字段菜单与类别下拉不传送到 body，避免被外层弹层判为外部点击。

**可编辑的已连接工作项卡片。** 卡片仅在服务端标明对端项目可见（`canOpen`）时，经普通 `getWorkItem`、项目、类别与标签接口加载完整详情；标题、类别、处理人、截止日期、状态、优先级复用表格的单字段命令与状态迁移，因此修改记入该工作项自己的单元格动态，卡片内提供「动态」页签。`canOpen=false` 或详情返回 403/404 时退回 13 字段最小只读卡片，不请求或扩大任何字段。看板上的 `readOnly` 只移除解除连接入口，不改变字段权限。

## Alternatives considered

- 采用 Monday 的「设为双向连接」复选框并持久化：未勾选的连接在目标项目表格中将完全不可见（「被连接」列已移除），还需迁移与契约变更；用户选择始终双向。
- 反向列只读：实现最简单，但用户要求两端可编辑，且只读会让目标侧仍需切换到来源项目维护连接。
- 为双向连接在目标项目创建真实列并双写连接行：解除、删除列与锁序都要同步两份事实，容易漂移；单行推导即可表达双向。
- 反向新建沿用投递语义（只需当前项目成员）：会让目标项目成员向来源项目写入，扩大投递面；要求两端成员即可满足协作且不新增授权。
- 为可编辑卡片扩展 `ConnectionCard` 投影：会把正文级字段暴露给非成员，违背最小卡片决策；改为在已有权限下走普通详情接口。
- 删除 `incoming`、`incomingTotal` 与入站分页端点：需要破坏性 OpenAPI 例外；保留兼容视图成本低且不增加查询次数。

## Consequences

本记录部分取代[连接列的表格体验](2026-09-30-connect-column-table-experience.md)中「被连接列」「对话框建列」与「卡片字段只读」的部分，原记录其余决定继续有效；连接筛选中的入站来源条件不变，文案改为「双向连接来源」，看板同时展示出站与双向连接（见[连接增强](2026-10-03-connection-enhancements.md)）。聚合、锁序与事件归属仍由[连接架构](../architecture/2026-09-30-work-item-connections.md)拥有。

`WorkItemConnectionIT` 覆盖按列窗口与兼容视图、反向搜索与新建的权限矩阵、`alreadyConnected` 方向、字段搜索与排序；`ConnectionHttpIT` 增加反向路由的状态码、幂等与闭合请求体用例（本地 Windows 环境因 JDK 无法建立回环管道无法运行 HTTP IT，由 CI 执行）。前端由 `connectColumnKeys`、`useConnectTable`、`ConnectColumnSetupPopover`、`ConnectItemPicker`、`ConnectCell`、`ConnectedItemCard` 等组件测试覆盖草稿列、自动命名、重命名、勾选与撤销、Add task、反向列与卡片三种权限形态；视觉验收区以静态数据源呈现建列流程、单元格、选择弹层与可编辑卡片。浏览器环境下的动效与弹层定位需人工复核。
