# Agent Note: 表格设置并发与默认状态

Status: implemented

## Problem

同一项目可以同时显示在多个仪表板表格或浏览器标签页。各实例读取一次后无条件整份 PUT，会让改行高覆盖另一个实例刚保存的着色规则。把个人默认状态套入所有分组的严格归组流程，还会在状态不可达或无迁移权限时锁住已完成创建的添加行。

本记录部分取代[工作项表格个人设置](2026-10-07-work-item-table-settings.md)中的无版本写入与非状态分组迁移失败策略。该记录继续拥有设置归属、展示、结构与作用范围。

## Decision

[设置接口](../../../../contracts/openapi/yumpoo-v1.yaml)的 GET/PUT 同时返回强 ETag 头与 `etag` 字段。版本取 `updated_at` 的 Unix 微秒数，未保存记录为 `"0"`；PUT 保留完整请求体，要求会话、XSRF 和 `If-Match`，缺失版本返回 428，过期版本返回 412。数据库以唯一键保护首次插入，以时间戳条件原子更新现有记录；每次成功写入至少推进一微秒，避免同一时间精度内写入复用版本。

[Web 保存队列](../../../../frontend/web-app/src/components/projects/useWorkItemTableSettings.ts)记录已确认快照和本地修改字段。412 后读取最新值，只自动合并双方改动不重叠的字段；默认值细化到每个字段，着色规则列表作为一个字段。相同字段被改为不同值时保留本地修改并显示冲突，用户点击“重试保存”才以本地修改覆盖该字段，关闭面板或继续修改其他字段不会隐式覆盖。该合并只用于个人表格偏好，不改变协作工作项的版本冲突策略。

网络故障、408、429 与服务端 5xx 失败后保留修改，以 1 秒、3 秒间隔最多自动重试两次；其他失败不自动重放。工具栏及菜单持续显示未保存状态和手动重试入口，成功后清除。待保存内容只保留在当前页面内存，刷新或离开页面不能保证恢复；保存错误不得显示为成功。

只有按状态分组的添加行需要严格完成目标归组，失败保留已创建项并仅重试迁移。其他分组与底部添加、下方插入统一调用 `applyDefaultStatus`：无权限、不可达、迁移失败或用户跳过说明时提示并结束本次添加，不回滚已创建工作项，也不重复创建。

## Alternatives considered

- 无条件整份覆盖：同一账号多个实例之间仍会丢失配置，不能满足跨设备保存语义。
- 只在 PUT 前重新读取：读取与写入之间仍有竞态，必须由数据库校验版本。
- 改为 PATCH：可避免无关字段互相覆盖，但同字段仍需冲突规则；当前完整结构校验和生成客户端已经存在，保留 PUT 配合版本与字段合并。
- 所有 412 均自动重放本地快照：会静默覆盖其他窗口修改；只合并不冲突的个人偏好。
- 所有分组都严格重试默认状态：默认状态是个人录入便利，无法迁移不应阻止继续创建；状态分组的目标归属才需要严格流程。

## Consequences

前后端需配套更新；不携带版本的旧客户端会收到 428。持久化结构不增加字段或迁移，版本由现有时间戳生成。着色规则列表发生并发编辑时不会自动按规则 ID 合并，避免改变规则优先级。`WorkItemHttpIT` 验证首次与后续过期写入、ETag 和缺失前置条件；`useWorkItemTableSettings.spec.ts` 验证双实例合并、同字段冲突、串行编辑、重试和项目切换；`useWorkItemGroupCreate.spec.ts` 验证非状态分组失败退出和状态分组严格重试。
