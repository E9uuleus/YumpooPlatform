# Agent Note: 工作项两级评论、共享置顶与统一删除

Status: implemented

## Problem

工作项评论需要承接主评论下的讨论，而单层时间线、15 分钟操作限制和独立治理删除入口不能满足当前协作方式。置顶与回复会改变列表组织，若直接改变原有时间游标排序或仅隐藏按钮，会产生历史漏项、越权删除和删除父评论后的孤立回复。

## Decision

本文部分替代[独立讨论契约](../architecture/2026-08-24-work-item-update-contract.md)的操作时限、删除能力、页面墓碑与事件版本，以及[富文本编辑器](2026-09-05-work-item-discussion-composer.md)的单层展示和附件入口决定。原记录继续拥有独立聚合、正文净化、Mention 身份、强 ETag、幂等、事务审计与草稿保护理由。

作者不限时编辑、删除自己的评论；当前 ProjectOwner 可删除所有评论，不能编辑他人评论。后端统一输出 canEdit/canDelete/canReply/canPin，不再公开截止时间、治理删除能力或理由输入。CompanyAdmin 只读；归档项目仍只允许当前 Owner 删除，不能发布、编辑或置顶。取消时间限制不取消可见性、成员资格或归档边界。

parentUpdateId 只指向相同工作项的未删除主评论；服务端禁止第三级。主评论删除授权包含删除整个讨论串（包括其他作者的回复），单独删除子评论仍要求该条作者或 Owner。发布、编辑、置顶、删除统一使用 Project → Content → Work Item → Update 锁顺序，整串删除逐条清空正文、记录版本和审计/Outbox，在同一事务提交。UI 明示级联范围并移除已删除记录；数据库保留作者、创建、编辑、删除事实及 Mention 快照。删除失败独立审计不包含正文。

所有可发表评论的成员可置顶、取消置顶任意主评论，允许多条，全员共享；子评论不置顶。重复设置相同状态不增版。普通主评论窗口按原创建时间/ID 游标覆盖全部未删除主评论，首页额外返回完整 pinnedItems，前端置顶优先并按 ID 去重。回复首批 20 条与数量随主评论返回，其余由独立正序游标读取，避免回复混入根窗口。刷新与置顶保留本地回复草稿。

评论头像复用 YpAssignee；时间向下取整显示刚刚、分钟、小时、天，悬停按公司时区显示年月日时分。主评论菜单提供 SVG 与文字，子评论采用浅灰气泡并保留相同身份和操作信息。已有子评论默认显示继续回复框；每串编辑器独立维护草稿、错误和幂等键，抽屉离开保护覆盖全部草稿。评论页面移除附件入口和请求，后台附件能力及历史文件不变。

V50 增加父评论与置顶字段，历史评论默认为根评论；移除 edit_deadline_at 及依赖其的生命周期限制。delete_reason 仅保留历史数据库事实，不作为当前删除输入或输出。发布、编辑、删除使用 v2 事件并带 parentUpdateId；统一删除模式为 SELF/ADMIN/PARENT_DELETE，不携带理由或正文。新增置顶事件 v1，Activity 显式订阅新版本和新事件；历史 v1 契约保持冻结。

## Alternatives considered

- 只在前端隐藏治理按钮：不能改变服务端理由分支和时限约束，也无法阻止越权请求。
- 删除主评论但保留回复：用户明确选择整串删除；确认文案需提示其他作者回复也会删除。
- 置顶排序直接混入历史游标：置顶/取消置顶会移动游标边界；额外置顶集合保留稳定的普通时间游标。
- 递归无限层回复：不符合两级协作要求，且会增加阅读、分页与授权复杂度。
- 改写冻结 v1 删除事件：新删除模式与去理由规则不兼容旧 schema，故新增版本并继续支持旧消费。

## Consequences

数据库、服务端、OpenAPI、生成 SDK 与前端需要配套升级；旧客户端不得继续依赖截止时间或治理能力。接口破坏变更按精确基线/当前哈希登记；不能用固定假截止时间维持旧行为。回滚旧服务端前必须恢复升级前数据库，不能直接对 V50 数据库运行旧服务端。

测试覆盖不限时作者操作、Owner/Member 权限、两级约束、跨工作项父引用、共享置顶、超过 20 条分页、幂等重放和删除/回复并发。视觉验收使用隔离组件数据，后端 HTTP 测试使用独立容器，不把页面预览当作真实接口验收。历史决策 Note 部分保留并交叉链接，冻结归档不修改。
