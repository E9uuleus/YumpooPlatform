# Agent Note: 工作项倒序讨论流与受限富文本编辑器

Status: implemented

## Problem

讨论在底部输入、向顶部加载历史的交互需要先定位列表末尾。项目需要类似 Monday Updates 的顶部输入与最新讨论优先，同时保证分页不漏历史、格式再次编辑不丢失、清单不会绕过讨论版本和编辑时限。

## Decision

本 Note 部分替代[独立讨论与生命周期治理契约](../architecture/2026-08-24-work-item-update-contract.md)的前端顺序、历史加载方向和富文本白名单决定。原 Note 继续拥有独立聚合、权限、15 分钟时限、强 ETag、幂等、墓碑、审计和事件隐私约束。

REST 继续按 `createdAt DESC, id DESC` 选择最新窗口，窗口内仍返回升序，`nextCursor` 继续指向更早记录。Web 将每批 20 条按创建时间和 ID 倒序去重展示，在抽屉 `.el-drawer__body` 的底部哨兵可见时追加旧窗口；没有内部列表滚动框，不足一屏继续补载。失败后停止自动重试。刷新成功替换整个已加载窗口及游标，避免合并最新一页与旧游标导致中间断档；请求代次和取消信号隔离过期响应。发布只插入服务端净化响应并回到顶部；编辑与墓碑仍按原创建位置显示。

发布和编辑共用 Tiptap 3.30.3 配置及工具栏。空白编辑器折叠为提示与 `@` 入口；聚焦展开，有文本或结构草稿时保持展开。个人 Mention 只列出 ACTIVE 项目成员，键入与按钮使用同一搜索、键盘选择和光标插入路径；不提供群组提及。Unicode 表情直接属于正文。附件继续由已发布讨论的附件入口管理；AI、云盘、定时或邮件发布、回复和点赞不属于本次能力。

服务端继续以显式标签白名单净化正文，新增 H2、下划线、删除线、代码块、分隔线、表格及清单。只有 span 可保存十六进制或整数 rgb 的文字色/背景色与 16、18、24、32、36、48px 字号；p/h2 可保存 left/center/right 对齐，指定块可保存 ltr/rtl 方向。表格跨度限制为 1–20，有序列表起始值为 1–10000。清单保存 `taskList/taskItem` 和布尔 `data-checked`，发布态以非交互标记显示，勾选修改必须走编辑讨论流程。未知样式、class、事件属性、图片和可执行内容仍被移除；链接和 Mention 身份继续服务端验证。HTML/纯文本长度限制及非空要求不变，无数据库迁移。

抽屉关闭、标签切换和工作项/路由切换共用草稿保护；写请求进行时暂缓离开。发布失败保留草稿及原幂等键，正文改变才更新键。页面内工具弹窗互斥并恢复选区；宽表格只在表格内横向滚动，窄抽屉工具栏换行。

## Alternatives considered

- 改变 REST 窗口为倒序：没有必要，会破坏已发布的客户端契约；展示排序由 Web 处理。
- 刷新仅合并最新 20 条：新记录超过一页时旧游标会跳过中间历史，因此采用完整窗口重建。
- 保存任意编辑器 HTML、内联样式和 checkbox 控件：扩大视觉欺骗与执行面，并允许发布态清单绕过版本控制，因此只保存所需格式和状态。
- 只做前端工具栏而不扩展净化器：发布后格式会消失，无法提供可靠的再次编辑体验。

## Consequences

前端、服务端、OpenAPI 白名单说明和富文本示例必须同步演进；扩展版本保持一致。旧讨论仍可读取和编辑。新格式由当前净化器保留，回滚到旧净化器后再次编辑会裁剪新增格式。该兼容限制不能通过任意 HTML 放行解决。

分页测试覆盖多批、相同时间、重叠记录、并发触底、失败重试、刷新与切换竞态；工具栏测试验证结构往返，服务端测试验证受限格式、恶意内容、身份及长度边界。浏览器验收应同时检查单层滚动、窄布局与草稿保护。
