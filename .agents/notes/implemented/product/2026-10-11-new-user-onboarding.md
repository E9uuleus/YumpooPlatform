# Agent Note: 新手引导与服务端处理记录

Status: implemented

## Problem

新成员经企微登录后直接进入[工作中台首页](2026-10-10-work-hub-and-my-time.md)，面对模块栏、Monday 风格工作项表格、仪表板、收件箱和计时器等密集入口，没有任何首次使用说明。引导需要判断“谁是新用户”。`/auth/me` 不含账号创建或首次登录时间，Electron 主窗口又使用独立持久分区，与浏览器不共享 localStorage；只靠前端记录，同一个人在浏览器和桌面端会各看一次，上线时存量用户也会被当作新用户。

## Decision

- **处理记录存服务端：** `GET /me/onboarding` 返回本人已处理的引导与版本，`PUT /me/onboarding/tours/{tourId}` 记录一次处理。写入按 `(company_id, user_id, tour_id)` upsert，版本只升不降，因此天然幂等，只要求会话与 XSRF，不使用 If-Match 或幂等键。tourId 只校验格式 `^[a-z][a-z0-9-]{1,47}$`，服务端不维护引导目录，新增引导不改契约。
- **归属 identityaccess：** 表 `yumpoo.user_onboarding_tour` 以 `(user_id, company_id)` 外键级联引用 `identity_user`。迁移把上线前已存在的账号的 6 个 v1 引导全部预置为已处理，存量用户不会看到自动引导。
- **形式：** 首页首次到达时弹出欢迎弹窗，可选择开始导览或跳过；导览使用 Element Plus `ElTour` 聚光灯与箭头气泡，不新增依赖。项目工作项、工作台、仪表板、收件箱、公司概览在首次打开时各自触发短导览，且必须等欢迎引导处理后才自动出现；同一时刻只运行一个。不做跨页面长导览、独立帮助页或任务清单。
- **判定口径：** 完成、跳过、关闭和 Esc 都记为已处理。引导内容版本定义在前端 `tours.ts`；提升版本会让已处理旧版本的用户再看一次。用户菜单“查看本页引导”只在本地重放，不写服务端。
- **目标定位：** 目标元素只加 `data-tour` 属性。启动时过滤掉不存在、无布局盒或位于 `[inert]` 内的步骤，覆盖移动端、侧栏折叠、看板视图和空表格，不为个别缺失目标写分支。读取记录失败时本次会话不自动触发任何引导，也不重试。

## Alternatives considered

- 前端 localStorage 按 `company:user` 作用域记录：零后端改动，但浏览器与桌面端各显示一次，清缓存后重现，且无法区分存量用户。
- 以 `identity_user.created_at` 或首次登录时间判定新用户：需要在 `/auth/me` 暴露新字段，仍要另存“已处理”状态，判定口径比显式记录更绕。
- 一条串联首页、项目、仪表板、收件箱的跨页面长导览：依赖用户已有项目数据，路由切换期间目标易缺失，比分页面导览更脆弱。
- 独立新手教程页：内容易随界面演进过期，用户很少主动查看。

## Consequences

每个账号每次会话额外一次 `GET /me/onboarding`，每处理一个引导一次 PUT。引导文案和目标随界面改动需要同步维护 `tours.ts` 与 `data-tour` 属性；目标被移除时对应步骤会静默跳过，不会报错。需要让存量用户重新看到某个引导时，提升该引导版本即可，不需要数据迁移。运维中心、项目成员/动态/设置、归档项目页没有引导。

## Verification

`OnboardingHttpIT` 覆盖新账号记录为空、写入后可读、低版本不降级且不改时间，以及非法 tourId 和版本返回 422。`useOnboarding.spec.ts` 覆盖欢迎引导门控、已处理不再触发、版本提升后重新触发和重放不重复写入。
