# Agent Note: 新手引导与服务端处理记录

Status: implemented

## Problem

新成员经企微登录后直接进入[工作中台首页](2026-10-10-work-hub-and-my-time.md)，面对模块栏、Monday 风格工作项表格、仪表板、收件箱和计时器等密集入口，没有任何首次使用说明。引导需要判断“谁是新用户”。`/auth/me` 不含账号创建或首次登录时间，Electron 主窗口又使用独立持久分区，与浏览器不共享 localStorage；只靠前端记录，同一个人在浏览器和桌面端会各看一次，上线时存量用户也会被当作新用户。

## Decision

- **处理记录存服务端：** `GET /me/onboarding` 返回本人已处理的引导与版本，`PUT /me/onboarding/tours/{tourId}` 记录一次处理。写入按 `(company_id, user_id, tour_id)` upsert，版本只升不降，因此天然幂等，只要求会话与 XSRF，不使用 If-Match 或幂等键。tourId 只校验格式 `^[a-z][a-z0-9-]{1,47}$`，服务端不维护引导目录，新增引导不改契约。
- **归属 identityaccess：** 表 `yumpoo.user_onboarding_tour` 以 `(user_id, company_id)` 外键级联引用 `identity_user`。迁移仅给有登录会话或成功登录审计记录的账号预置全部 6 个 v1 引导；过期会话也证明曾登录，成功审计可覆盖会话已清理的老用户。仅由企微通讯录同步创建、没有登录证据的账号仍会看到首次引导。
- **形式：** 首页首次到达时弹出欢迎弹窗，可选择开始导览或跳过；导览使用 Element Plus `ElTour` 聚光灯与箭头气泡，不新增依赖。项目工作项、工作台、仪表板、收件箱、公司概览、我的工时、我的一天、团队视图和工作日历在首次成功加载页面数据后各自触发短导览，且必须等欢迎引导处理过（任一版本）才自动出现；加载失败不触发，重试成功后仍有资格，同一时刻只运行一个。路由元数据统一定义自动触发与菜单重放的引导归属；触发绑定页面生命周期，引导记录返回后再次检查页面数据就绪状态，离页取消弹窗、导览和待返回请求的触发资格，不计为已处理。不做跨页面长导览或任务清单；独立帮助文档见[文档中心](2026-10-20-docs-site.md)，欢迎弹窗的「浏览帮助中心」记为已处理欢迎引导后打开文档中心，导览只负责实时界面讲解。
- **判定口径：** 自动引导的完成、跳过、关闭和 Esc 都记为已处理。引导内容版本定义在前端 `tours.ts`，每个步骤用 `since` 标注引入或内容实质变化时的版本（缺省为 1）。新用户看完整导览；已处理旧版本的用户进入增量模式，只看 `since` 晚于其已处理版本的步骤，标题带“新功能”标签，完成后记为新版本，增量模式不要求欢迎引导已处理到当前版本；没有新增步骤的升版直接静默写入新版本。顶栏“查看本页引导”按钮使用独立重放模式（当前页面没有导览时禁用），无论服务端是否已有处理记录，始终展示完整导览，均不写服务端或改变本地处理状态。
- **目标定位：** 目标元素只加 `data-tour` 属性。启动和窗口缩放时过滤掉不存在、无布局盒或位于 `[inert]` 内的步骤；缩放更新合并为每帧最多一次，重新计算窄屏位置并保留当前目标，覆盖移动端、侧栏折叠、看板视图和空表格，不为个别缺失目标写分支。步骤可声明 `fallback` 备用目标与说明：二级导航收起（`inert`）时，指向二级导航的步骤改指模块栏的展开按钮，主目标与备用目标都不可见才跳过。`tours.spec.ts` 从源码收集 `data-tour`，校验每个步骤的目标与备用目标存在、路由引用的导览存在且除欢迎外每个导览都有路由触发，以及 `since` 与版本一致。读取记录失败时本次会话不自动触发任何引导，也不重试。

## Alternatives considered

- 前端 localStorage 按 `company:user` 作用域记录：零后端改动，但浏览器与桌面端各显示一次，清缓存后重现，且无法区分存量用户。
- 以 `identity_user.created_at` 或首次登录时间判定新用户：需要在 `/auth/me` 暴露新字段，仍要另存“已处理”状态，判定口径比显式记录更绕。
- 迁移时按账号存在与否区分新旧用户：企微预同步也会创建账号，不能证明成员用过平台，因此回填采用已有登录证据。
- 一条串联首页、项目、仪表板、收件箱的跨页面长导览：依赖用户已有项目数据，路由切换期间目标易缺失，比分页面导览更脆弱。
- 独立新手教程页：内容易随界面演进过期，用户很少主动查看。已由文档中心以“概念与规则”定位替代，导览仍不做独立教程页。

## Consequences

每个账号每次会话额外一次 `GET /me/onboarding`，每处理一个自动引导一次 PUT。引导文案和目标随界面改动需要同步维护 `tours.ts` 与 `data-tour` 属性；运行时目标缺失的步骤静默跳过，源码中删掉或改名的目标由 `tours.spec.ts` 拦截。需要让存量用户看到改动时，提升该引导版本并给新增或实质改动的步骤标注新的 `since`（测试要求升版的导览至少有一个当前版本的步骤），不需要数据迁移；新页面导览对存量用户首次进入同样会出现。如果历史登录会话和成功审计均已清理，迁移无法证明其使用历史，会保留自动引导资格。运维中心、项目成员/动态/设置/统计、归档项目页、公司管理除概览与工作日历外的页面没有引导。

## Verification

`OnboardingHttpIT` 覆盖新账号记录为空、写入后可读、低版本不降级且不改时间、非法 tourId 和版本返回 422、缺失或错误 XSRF 被拒绝，以及不同用户的读写隔离。`OnboardingMigrationIT` 从 V69 升级到 V70，验证会话与成功审计回填、重复证据去重、未登录同步账号与迁移后新账号不回填。`useOnboarding.spec.ts` 覆盖欢迎门控、版本提升、无记录或读取失败时重放不写入、异步加载后离页与会话切换、数据就绪状态复查；相关页面测试覆盖加载失败不触发和恢复后触发。`useOnboarding.spec.ts` 另覆盖旧版本进入增量模式并写入新版本、欢迎引导增量模式不弹窗且页面增量不等欢迎、无新增步骤静默升版、旧版本重放仍完整且不写入。`OnboardingHost.spec.ts` 覆盖路由取消、重复首页跳转保持欢迎弹窗、缩放定位与当前目标保持、连续缩放合帧和取消待执行帧、增量模式只渲染新步骤并显示“新功能”标签，以及主目标在 `[inert]` 内时改用备用目标与说明。`tours.spec.ts` 校验导览目标、路由引用与版本标注；我的工时、我的一天、团队视图与工作日历的页面测试覆盖加载成功后触发、加载失败不触发。本地冒烟（`pnpm test:e2e`）在真实浏览器中走过欢迎弹窗与页面导览。
