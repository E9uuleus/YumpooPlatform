# Agent Note: 项目页头菜单与平整设置

Status: implemented

## Problem

页头五个分区图标按钮与侧栏重复，无法容纳项目操作。通知藏在标题弹层，结束和归档只在设置页，成员自主退出也需要可见入口。

## Decision

- 页头统一为单一 ⋯ 菜单，分为项目页面、项目操作两组；当前页标记，仅按服务端 capabilities 显示生命周期和退出操作，通知提醒按项目访问身份显示。
- 三个省略号职责分离：页头管理项目，表格工具栏管理表格设置，行内管理工作项。标题弹层只显示负责人、创建时间和管理员只读说明。
- 此入口部分取代[项目通知偏好](2026-10-06-project-notification-preferences.md)的标题内通知入口；通知保存、过滤与可见性规则仍由原记录拥有。
- 生命周期逻辑移入 useProjectLifecycleActions，由设置页和菜单共用。页面通过页头 changed 事件刷新项目，设置页使用 load(false) 保留草稿，412 后也保留草稿。
- [成员自行退出](2026-10-31-project-self-leave.md)入口为红字菜单项，确认说明退出后失去访问权、停止本人当前项目计时、保留历史记录及重新加入方式。
- 设置改为单栏，依次是项目概要、基本信息、连接、项目状态与危险区域；首次读取无数据时显示表单骨架。

## Alternatives considered

- 仅把四个页面收入菜单而保留工作项按钮：入口仍分散。
- 照搬参考产品的 AI、Power-Ups、删除看板：没有对应能力，不放虚假入口。
- 在菜单即时永久删除：继续使用归档列表的计划删除流程，保留缓冲期。

## Consequences

导览目标 project-sections 移到 ⋯ 按钮，项目导览升级到版本 5。分区在侧栏当前项目与菜单中各有一处入口。菜单能力、退出返回工作台和设置草稿保护沿用服务端与既有页面逻辑。
