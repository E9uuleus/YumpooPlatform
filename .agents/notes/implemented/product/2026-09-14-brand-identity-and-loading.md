# Agent Note: 品牌资产与界面主题分离

Status: implemented

## Problem

网页、标签页与 Windows 托盘此前分别使用文字 Y 或程序绘制图标，打包 EXE 还保留 Electron 图标。直接使用附件的白底与宽留白会影响深色主题和小尺寸识别；品牌金色也不能取代现有行动色与状态色。

## Decision

以用户审核通过的金色云形与三个人形作为统一品牌。透明母版位于 `tools/branding/logo-master.svg`，保留审核版本的金色纹理和分组轮廓；固定版本 resvg 从母版确定性导出网页 SVG、favicon 与 Windows 多尺寸 ICO/PNG，CI 检查导出漂移。母版内部的纹理和路径只描述品牌，不引用主题令牌。

`vBrandLoading` 包装 Element Plus 原有加载指令，沿用条件、遮罩范围及生命周期。云形渐显、三个人形依次亮起与整体轻微呼吸采用 2.4 秒循环；完成加载即可退出，不设置最短等待。系统要求减少动态效果时保留静态图标及加载文字。按钮忙碌图标、骨架屏与计时器交互动效维持各自职责。行动色、状态色、背景色与三主题切换继续由现有令牌管理。

窗口和托盘从统一 PNG 加载图标，ASAR 只加入所需 PNG。Windows 打包用固定 `resedit@3.1.0` 替换复制后的 EXE 图标组；不改安装依赖中的 Electron 原件。产物检查比较所有图标尺寸的字节与母版导出资源，ASAR 保持精确白名单。修改 PE 资源后产物没有原 Electron 的签名；如交付渠道要求签名，应在资源写入完成后对最终产物签名。

本决策更新[计时窗与托盘决策](2026-09-08-timer-work-picker.md)中的品牌外观，不改变托盘入口和计时生命周期。

## Alternatives considered

- 直接缩小白底附件：深色页面产生白色块，原留白使标签与托盘标识过小。
- 按主题重绘或使用金色作为行动色：会改变用户已确认的品牌和现有主题语义。
- 继续保留独立手绘托盘图形或 Electron EXE 图标：平台之间无法保持统一，也不能由同一资源检查证明一致。
- 自建加载遮罩生命周期：重复 Element Plus 的滚动、目标定位与卸载职责，增加回归风险；包装现有指令即可满足动效需求。

## Consequences

品牌调整从母版重新导出五个产物；共享加载实现需要为多个并存 SVG 的内部引用分配唯一 ID。运行时只使用本地静态资源。名称输入框保持 ElInput 与原有保存、取消、输入法和失败重试行为，由名称单元格拥有选中/编辑边框，局部消除全局表单高度和外扩焦点轮廓的冲突。

加载生命周期与名称编辑行为由前端回归验证，布局错位仍以浏览器真实布局检查为准；Windows 原生图标识别同时依赖真实 Electron smoke 与 EXE/ASAR 资源检查。
