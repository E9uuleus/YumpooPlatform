# Agent Note: 工作中台首页与本人工时日历

Status: implemented

## Problem

成员只能在计时器里看到单个工作项的累计时长，无法按自然日核对自己的工时；按日统计只存在于[团队视图](../security/2026-10-08-admin-team-reporting.md)，且只对 COMPANY_ADMIN 开放。登录后的 `/` 被替换到管理项目目录，没有汇总本人待办、工时与常用入口的起点页面。新增本人统计接口会在管理员报表之外开出新的读取边界，首页 hero 的持续动效也超出了 [Canvas 氛围动效](2026-09-30-canvas-ambient-motion.md)原有的适用范围，二者都需要明确记录。

## Decision

- **本人接口：** `GET /me/timesheet` 与 `GET /me/current-tasks` 对任意有效成员开放，只读本人数据。
  - 计时固定为 `actor.userId()` 的未删除计时，排除已删除工作项；当前任务固定为分配给本人、未删除未归档且状态分类为 TODO 或 IN_PROGRESS 的工作项。
  - 项目范围沿用[私人仪表板](2026-09-16-personal-dashboards.md)的 `MemberProjectQuery`：本人当前有效成员身份的未归档项目，最多 100 个。
  - 自然日切分、跨日按重叠时长拆分、运行中计时统计到 asOf，与团队视图同一口径；区间最多 93 天。响应复用 `TeamTimesheet`（`members` 只含本人）与 `TeamMemberTaskPage`。
  - workitem 的 `TeamWorkQuery` 新增不做管理员校验的 `ownTimeEntries` 与 `ownCurrentTasks`，用户由端口固定为当前主体，复用团队视图的同一组 SQL。接口只读、`no-store`、不写审计。
- **工时日历入口：** 仪表板标签栏首位固定标签「我的工时」，使用保留路由 ID `my-time`，所有成员可见，管理员的「团队视图」排在其后；不新增路由。首页「我的工时」卡片直达该标签。日历为周一开始的 6×7 网格，点击日期查看按项目分组的工作项明细。
- **首页：** `/` 发布为工作中台首页（路由名 `home`，`shellSection: 'home'`）。模块栏首项与品牌 Logo 指向首页，首页不渲染二级子菜单。`/workspace` 继续替换到个人工作台规范地址，管理项目目录不变。
- **首页动效：** hero 使用 Canvas 场景 `auroraShapes`：按时段切换色板的极光光晕、左侧表面色渐隐、按深度视差的悬浮几何与固定种子颗粒，30fps。这是非工作面的氛围动效例外；工时日历与首页卡片只使用一次性入场与悬停微交互。

## Alternatives considered

- 放开团队视图接口给普通成员并在服务端按本人过滤：管理员端口与成员端口共用一套授权语义，后续扩展筛选条件时容易越权。
- 个人范围沿用团队视图的全公司未归档项目：数字与管理员视图完全一致，但已退出项目的成员仍能读取该项目的工作项标题，违背私人统计只看有效成员项目的先例。
- 工时日历做成独立页面或一级模块：入口更外层，但增加路由与页面层级；用户选择了仪表板固定标签，并由首页卡片直达。
- 保留未发布的旧 HomeView：只有身份卡片，没有数据与动效，不能承担工作中台入口。

## Consequences

成员离开项目或项目归档后，该项目的计时与任务不再出现在个人日历和首页，但仍按团队视图规则计入管理员统计，此时两边数字会不一致。首页加载会额外请求本周工时、当前任务（最多 100 条）、成员项目与项目总数。[个人工作台规范路由](2026-08-24-personal-workspace-route.md)中“`/` 替换到工作台、首页路由不再发布”的结论由本 Note 部分替代，其余别名与目录规则继续有效。

## Verification

DashboardHttpIT 验证本人工时只返回本人计时、超过 93 天返回 422，当前任务只返回分配给本人的未完成工作项。前端路由测试覆盖 `/` 停留在首页与 `/workspace` 规范化，仪表板标签测试覆盖固定标签顺序与选择。
