# Agent Note: 工作项富文本描述与内嵌附件图片

Status: implemented

## Problem

工作项详情抽屉的“详情”标签只读展示类别、状态、优先级、处理人、截止日期、更新时间、纯文本描述和附件面板。字段已能在表格中直接编辑，描述却没有任何编辑入口，也无法插图，详情页因此不能承担“这个工作项具体要做什么”的内容载体。描述原为最多 16 KiB 的纯文本，讨论富文本净化器又明确移除图片；附件下载强制 `Content-Disposition: attachment`、`no-store` 与 `CSP: sandbox`，生产 CSP 只允许同源图片。

## Decision

本 Note 部分替代[工作项核心契约](../architecture/2026-08-22-work-item-core-contract.md)中“描述规范化为最多 16 KiB 纯文本”的决定；备注仍为纯文本，其余字段、锁序、ETag、事件与幂等理由继续由原 Note 持有。讨论正文的白名单、Mention 与编辑规则仍由[讨论编辑器决定](2026-09-05-work-item-discussion-composer.md)持有。

`work_item.description` 成为唯一描述真源，保存受限协作富文本 HTML。服务端描述净化档复用讨论白名单与样式归一化，另允许 `img[src,alt]`；`src` 必须精确匹配同源 `/api/v1/attachments/{uuid}/content`，其余图片地址（绝对 URL、协议相对、`data:`、`javascript:`、带查询串）整体移除，`alt` 截断到 255 字。Mention 在描述中降级为纯文本，不校验成员、不触发提醒。净化后 HTML 最多 65536 字、纯文本最多 16384 字；既无文本又无图片时保存为 null。净化结果幂等，使改名等全量快照回传原描述时仍为无版本、无事件 no-op。创建、子项创建、全量 PATCH 与新增 `PATCH /work-items/{id}/description` 共用同一净化入口；新命令沿用单字段命令的 XSRF、强 If-Match、持久化幂等键和 `work_item_fields_changed(changedFields=[description])`，事件仍不携带正文，Activity 继续过滤描述变更。V55 将历史纯文本按行转义为 `<p>` 段落，不推进版本或更新时间。

服务端不校验图片附件是否属于当前工作项：workitem 不反向依赖 filestorage，下载端点每次实时复核父对象读取权，引用他项附件的图片对无权读者只显示为损坏图片，不泄露内容。

Web 详情标签只保留描述区。查看态直接渲染服务端净化结果，点击图片用 Element Plus 图片查看器放大，点击正文进入编辑；空描述可写时显示“添加描述”入口，只读时显示“暂无描述”。编辑态复用讨论工具栏（隐藏 @ 提及，新增插入图片），显式保存/取消。图片可按钮选择、粘贴或拖入，前端仅接受 PNG/JPG/GIF 且单张不超过 20 MiB；每张图片先以编辑器内占位块表示“上传中/安全扫描中/失败原因”，复用附件意图 → PUT → 1/2/5 秒轮询（最长 5 分钟）协议，扫描通过后在撤销历史之外替换为同源图片节点。存在未完成图片时禁止保存；取消、放弃或关闭会中止轮询。412 冲突保留草稿与幂等键，只提供“放弃草稿并载入最新”，不自动重放。详情页常驻挂载，切换标签不丢描述草稿；关闭抽屉、切换工作项或路由离开时统一确认丢弃描述与讨论草稿。保存或载入最新后的 `WorkItemDetail` 同步回表格行，保证后续单元格编辑使用新 ETag。

备注与既有工作项附件保留在数据库与 API 中，详情页不再展示；未被引用的 `WorkItemDetailsDrawer` 已删除，附件面板组件暂无页面入口。

## Alternatives considered

- 新增 `description_html` 列并保留派生纯文本 `description`：全量 PATCH 中的旧字段与新列会形成双真源，需要额外的冲突规则，拒绝。
- 常驻编辑并自动保存：与“412 不自动重放、保留草稿”的既有并发约定冲突，且图片扫描期间的保存时机难以表达，拒绝。
- 在 CSP 中放行 `blob:` 以即时预览本地图片：改变部署安全边界，仅换取扫描期间的缩略图，采用占位块替代，拒绝。
- 前端以 Base64 内嵌图片：绕过附件查毒、配额与审计，且放大正文长度，拒绝。
- 由服务端校验图片附件归属：需要 workitem 依赖 filestorage 或新增跨模块端口，而下载侧已逐次鉴权，收益不足，暂不采用。
- 迁移时把备注并入描述、或保留只读历史附件列表：用户选择仅隐藏入口、数据保持不变，保证最小改动与可回退。

## Consequences

OpenAPI 将描述上限从 16384 扩为 65536，响应侧放宽被兼容检查识别为破坏变更，已按精确哈希登记一次性例外；生成 SDK、服务端、前端必须同步升级。回滚到旧服务端前需要恢复 V55 前数据库，否则旧客户端会把 HTML 当作纯文本显示。附件下载仍为 `no-store`，描述中的图片每次渲染都会重新下载；在线预览、缓存策略与 Range 仍由附件后续决策负责。编辑中删除或取消的图片、未保存草稿里已上传的图片会留下无引用的工作项附件，由后续附件清理策略处理。

## Verification

净化器单测覆盖图片地址允许/拒绝、属性剥离、Mention 降级、仅图片内容、空内容清空、格式保留、幂等与长度边界；`WorkItemHttpIT` 覆盖新命令的净化、事件字段、幂等重放、同键异参 409、旧 ETag 412、缺少 If-Match 428、无变化 no-op、超长 422、全量快照回传不改描述、清空与归档后不可写。前端测试覆盖查看/空/只读状态、图片查看器、无提及按钮、ETag 与幂等键保存、清空为 null、412 保留草稿与载入最新、上传占位替换、失败移除、类型拒绝、取消中止上传，以及标签切换只保护讨论草稿、关闭时汇总丢弃。
