# Agent Note: 仪表板控件跨分辨率保持高度

Status: implemented

## Problem

根据列宽推导接近方形的最小高度，以及在 medium 和窄屏使用独立高度，会使控件在不同显示器或窗口宽度下纵向尺寸跳变。用户希望响应式布局只调整宽度和排列，高度保持已设置的值。

## Decision

共享高度变化后两个断点的位置整理与即时保存由[自动避让与窗口独立保存](2026-09-19-dashboard-layout-autosave.md)补充；不能只同步高度而保留可能重叠的位置。

本记录部分替代[仪表板保存恢复与展开视图](2026-09-18-dashboard-recovery-and-exploration.md)中的方形最小高度与独立断点高度策略，其保存恢复、手动刷新及统一弹窗规则继续有效。

[DashboardGrid](../../../../frontend/web-app/src/components/dashboard/DashboardGrid.vue) 保留 40px 固定行高，以 wide.h 作为所有断点共用的高度。既有 medium.h 不再独立决定显示高度；该兼容选择不需要数据库迁移或视口变动时的自动保存。最小高度固定为 3 行，不根据列宽或图表类型推导。宽度与横向位置继续采用当前断点的布局，窄屏按各控件的真实高度累计纵向位置，避免固定间隔造成重叠。

用户主动拖动或缩放时，仍按手势结束时的实际列数保存横向布局，当前高度同步写入 wide.h 和 medium.h。视口变化本身不触发保存，过期手势保护继续有效。已有控件的高度和新建控件的默认高度不作批量重置。

所有控件共用 22px 标题、72px 最小标题栏与 1px 底部分割线，数字控件不再覆盖成较小字号。标题截断与操作菜单保留，图表占用标题栏以下剩余空间。

## Alternatives considered

- 保持接近方形：宽度变化会强制改变高度，不符合跨显示器稳定的要求。
- 引入第三个独立高度字段并迁移所有布局：现有 wide.h 足以提供统一来源，新增字段会增加契约及迁移成本。
- 完全禁用手动高度缩放：用户要求限制响应式自动变化，仍应保留主动调整控件大小的能力。

## Consequences

旧数据若两种布局高度不同，以 wide.h 为准。控件位置与宽度可随断点重排，纵向像素高度保持不变。尺寸采用 CSS 像素，不承诺浏览器缩放或操作系统 DPI 变化后的物理尺寸不变。

## Verification

网格组件与真实引擎共 7 项测试通过，覆盖断点切换高度、窄屏累计布局、手动尺寸同步和过期手势。类型检查与生产构建通过。浏览器在 1920×1080、1280×720、900×900、390×844 测量所有控件，高度分别保持原值，当时标题均为 26px、分割线均为 1px；标题随后按用户反馈收小至 22px，行高调整为 30px。
