# Agent Note: 我的一天时间线填报、计时器开关与上班时间

Status: implemented

## Problem

[并行计时决策](../architecture/2026-10-14-parallel-time-tracking.md)上线的“我的一天”是叠在月历上的抽屉：拖选后在侧栏用 datetime-local 和复选框列表补录，保存前必须先在并行、替换、仅补空白三种方式中选一种；按时长补录是另一个带独立时间线的对话框。只要当天有一处重叠，所有记录块都变成半宽；已有记录不能直接拖动调整，也不能改到其他工作项。计时器无法关闭，只手动填报的人仍看到全部计时入口，而且“最近”候选只认计时器会话，手动补录过的工作项不会出现。

## Decision

### 独立的日页面

月历仍是“我的工时”入口。点击日期、“今天”或日期弹层的“时间线”进入 `/workspace/:slug/my-time/day/:date`，旧的 `?day=` 链接重定向到该路由；“返回月历”带 `?month=` 回到原月份。页头显示日期切换、日类型和当天已记录合计，不显示标准工时进度，←/→ 切换日期、T 回到今天。

- 时间线 1 分钟 1.6 像素（15 分钟 24 像素），画布以 15 分钟吸附点阵为底，按公司时区当天的真实起止绘制。上班时段外浅色、现在之后加斜纹且不可操作，并显示“现在”线。
- 记录卡片沿用工作项表格的左侧色条，只显示标题、项目和时长，不显示工作项编号，卡片上下左右留出间距。时段显示在左侧时间轴：悬停记录时标出起止；拖动、拉伸、拖选、从侧栏拖入和按时长预览时显示预览时段。不足 15 分钟的记录（多来自计时器）从裁剪到当天的起点按 15 分钟高度绘制，并按绘制高度参与分列，因此跨零点的短尾段也不会压在相邻记录上；`÷N` 与当天计入时长仍按真实重叠计算。空白提示从卡片绘制结束处显示，快捷按钮保持可见和可点，补录仍使用真实空白时段。
- 只有绘制范围相互重叠的记录簇分列显示，真实并行时标出 `÷N`，提示中给出当天计入时长；当天计入与“今天已记录”合计都在前端按 1/N 切分计算，与服务端口径一致。
- 上班时段内不少于 15 分钟的空白显示“空白 Xh · 补录”快捷按钮，也是键盘创建入口。

### 填报交互

- 在空白处拖选（15 分钟吸附，Alt 为 5 分钟）或单击（1 小时并裁剪到所在空白）后，选区旁弹出补录面板：时间可直接输入，搜索框自动聚焦，单击工作项即保存；⌘/Ctrl 单击可多选，一次添加多项并行记录。Web 新建输入时段最短 15 分钟：短拖选在起点所在空白内补足，下方有记录或临近现在时向上扩展；空白不足 15 分钟则提示并拒绝。补录面板、侧栏自定义时长和计时日志的手动添加同样拒绝更短的输入时段。
- 没有重叠时不出现任何方式选项，静默按 GAPS 提交。与已有记录重叠时才显示“只填空白 | 并行均摊 | 覆盖”，默认只填空白；所选时段已全部有记录时默认并行均摊并禁用只填空白；重叠记录都不可修改时禁用覆盖。下方实时说明各方式的效果。
- 点击记录在原位编辑起止时间、更换工作项、删除（二次确认）；并行时可“独占此时段”，等于对该项该时段执行 REPLACE。运行中、跨日的一侧和不可编辑记录只读并说明原因。
- 拖动记录主体移动、拖上下边缘拉伸，松手即保存，失败回滚。拖动只能停在“开始拖动时未与之重叠”的相邻记录之间，同一工作项的其他记录总是障碍，因此拖动不会制造新的并行。
- 侧栏列出今天已记录和“最近与我的”工作项。侧栏提供“最近与我的 | 全部”范围、“分配给我”和按项目筛选，任一筛选或搜索时只显示结果列表；筛选在已加载的候选上进行，没有新增服务端参数。搜索使用全部范围，范围控件显示“全部”并禁用，清空搜索后恢复原范围；已选项目即使不在当前候选中也保留零计数选项，可单独取消。项目筛选复用 `el-checkbox`；今天已记录与候选均只用色条标识类别，不额外显示类别胶囊。“＋”提供 0.5h、1h、2h、4h 和自定义时长，悬停即在时间线上虚线预览，点击后从上班时间起依次排入空白，可跨多段，最多 20 段，跳过不足 15 分钟的空白；分配会为后续空白预留至少 15 分钟的尾段，不足两段最小时长时优先寻找能完整容纳的后续空白，无法排入时提示剩余时长。桌面浏览器可把工作项直接拖到时间线，在落点生成 1 小时并裁剪到所在空白；触屏改用单击和“＋”。
- 计时日志的手动添加表单使用同一套重叠控件和默认值。

“按时长补录”对话框、抽屉和固定的三选一单选随之删除。

### 改归属

`POST /me/time-sessions/{sessionId}/reassign` 要求该记录的 If-Match，在 fill 的同一锁顺序和事务内软删除原记录，再按 PARALLEL 在目标工作项补同一时段，只跳过目标项自身已有的部分。沿用 deleted 与 added 事件，新记录为 MANUAL。没有选择原地 PATCH 换工作项，因为那样原工作项收不到移除事件，活动投影会出错；也没有给 fill 增加待删列表，以免把单条记录的版本校验混进不要求 If-Match 的批量补录。

### 计时器开关与上班时间

`work_item_timer_state` 增加 `timer_enabled`（默认 true）、`workday_start_minute`、`workday_end_minute`（默认 540、1080），通过 `CurrentTimeTracker.preferences` 返回，`PUT /me/time-tracker/preferences` 以计时状态 ETag 保存。偏好与计时状态共用用户状态锁和版本号：关闭时在同一事务内停止本人全部运行计时，关闭后 start、switch 返回 409 `TIMER_DISABLED`，stop 与 stop-all 仍可用。代价是保存偏好会让其他窗口进行中的计时命令以 412 刷新重试。

工时设置和工作项表格“时长追踪”列菜单的“设置”中提供同一开关，与上下班时间编辑共用计时器的忙状态，保存期间互斥。计时器关闭后，Web 隐藏右下角入口并忽略打开事件，工作项表格不再显示启停按钮（该项仍在运行时除外），时长居中显示，首页计时卡改为“记录工时”进入今天，项目工作项工具栏隐藏“小计时器”。桌面状态增加可选的 `timerEnabled`：关闭时主进程不再自动弹出悬浮球，`show` 改为打开主界面，托盘与快捷面板去掉继续、查找、显示方式和置顶；旧版桌面壳不认识该字段，由 Web 调用 `hide()` 兜底。Web 按浏览器缓存最近一次的开关，避免计时入口在首次轮询前闪现，退出登录时清除。

上班时间只用于空白提示、按时长排入的起点和打开时的滚动位置，不参与统计、提醒或加班口径。每日标准工时取公司日历：`TeamTimesheetDay.standardMinutes` 新增，月历格的填满程度使用它；日页面不显示标准工时，月历非工作日回退为 8 小时参考值。

计时候选的“最近”改为包含手动补录，否则只手动填报的人在侧栏和补录面板中只能看到分配给自己的工作项；`recentItems` 与 `resumeItems` 仍只看计时器会话，因为它们驱动“继续”。

## Alternatives considered

- 保留抽屉，只简化侧栏表单：月历上叠放的窄抽屉无法同时容纳时间线、工作项列表和就地编辑。
- 日视图作为“我的工时”的默认页：用户选择保留月历作为入口。
- 重叠时默认并行均摊：手动填报的重叠多数是拖过头，默认并行会悄悄改变已有记录的计入时长。
- 每次重叠都强制选择方式：多一步确认，且大部分情况答案相同。
- 计时器开关只存浏览器：Web、桌面与不同浏览器之间不一致，服务端也无法拒绝其他入口的开始。
- 独立的偏好表：关闭计时器需要与停止计时在同一锁内完成，另建表还要再定一套锁顺序。
- 日页面保留“已记录 / 标准工时”进度，或改成个人标准工时设置：标准工时由公司日历决定，个人不能调整，进度条反而让人以为可以设置；用户选择只显示已记录合计。
- 短记录保持真实高度：几分钟的记录只剩一条细线，既看不清也难以点中。
- 侧栏筛选走服务端参数：要改契约；“最近与我的”候选通常是有限集合，前端筛选已经够用，“全部”范围下未加载的项通过“加载更多”补齐。
- 为侧栏类别胶囊扩展工时接口：当前工时接口只有类别色，没有类别名称；两区统一使用已有色条，避免同一工作项记录前后样式不一致。

## Consequences

日页面的空白、均摊、布局和吸附都在前端计算，并以服务端规划器为准；客户端预览与服务端结果不一致时，以保存后的重新加载为准，并提示跳过的时长。拖动和就地编辑使用既有 PATCH，若拖动期间其他窗口改动了相邻记录，仍可能产生并行，由服务端按 1/N 计入。

15 分钟是 Web 新建时的输入约束，不是服务端持久化约束。已有记录编辑和服务端 GAPS 裁剪仍沿用原有行为，直接 API 调用或按真实空白裁剪后的结果可以短于 15 分钟；这些记录按最小绘制高度显示，统计仍取真实时长。

计时器关闭会停止全部运行计时，保留已记录的会话、报表与统计，同时隐藏入口并拒绝新的计时；重新开启只恢复入口，不自动恢复已停止的计时。桌面需要随本次发布更新才能完全隐藏托盘入口，旧版桌面仅隐藏悬浮窗。偏好保存推进计时状态版本，属于用户状态锁上的少量额外冲突。

## Verification

Web 模型与组件回归覆盖短空白拒绝、临近现在时向上补足、短记录和跨零点尾段分列、按时长排入预留有效尾段、搜索范围和项目筛选状态、计时器设置保存互斥，以及关闭月历明细后取消延迟切换。均摊测试独立使用真实时段，确保绘制外延不会改变计入时长。

既有 HTTP 回归确认独占目标记录可以只删除其他记录，计时器关闭会停止跨项目的全部运行计时，重新开启不会自动恢复。Web 组件回归覆盖仅删除、裁剪或拆分重叠记录、没有实际变化，以及覆盖补录仅删除和只填空白无变化时的反馈。

本机交互验收覆盖拖选和就地补录、移动拉伸、从侧栏拖入、按时长预览、短记录分列、真实重叠标识、时间轴时段、计时器开关同步与关闭确认、月历明细进入路径及浅色和深色主题。桌面回归覆盖计时器控制器、preload 与渲染页面；托盘实点操作不在此验证范围内。

验证命令为 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm run doc-sync` 和 `pnpm run test:agent-notes`。具体执行次数、结果数量和本机环境差异记录在 PR 中。
