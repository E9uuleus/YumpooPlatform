# Agent Note: 我的一天时间线填报、计时器开关与上班时间

Status: implemented

## Problem

[并行计时决策](../architecture/2026-10-14-parallel-time-tracking.md)上线的“我的一天”是叠在月历上的抽屉：拖选后在侧栏用 datetime-local 和复选框列表补录，保存前必须先在并行、替换、仅补空白三种方式中选一种；按时长补录是另一个带独立时间线的对话框。只要当天有一处重叠，所有记录块都变成半宽；已有记录不能直接拖动调整，也不能改到其他工作项。计时器无法关闭，只手动填报的人仍看到全部计时入口，而且“最近”候选只认计时器会话，手动补录过的工作项不会出现。

## Decision

### 独立的日页面

月历仍是“我的工时”入口。点击日期、“今天”或日期弹层的“时间线”进入 `/workspace/:slug/my-time/day/:date`，旧的 `?day=` 链接重定向到该路由；“返回月历”带 `?month=` 回到原月份。页头显示日期切换、日类型和“已记录 / 标准工时”进度，←/→ 切换日期、T 回到今天。

- 时间线 1 分钟 1 像素，按公司时区当天的真实起止绘制。上班时段外浅色、现在之后加斜纹且不可操作，并显示“现在”线。
- 只有相互重叠的记录簇分列显示，每块标出 `÷N`，提示中给出当天计入时长；当天计入与“今天已记录”合计都在前端按 1/N 切分计算，与服务端口径一致。
- 上班时段内不少于 15 分钟的空白显示“空白 Xh · 补录”快捷按钮，也是键盘创建入口。

### 填报交互

- 在空白处拖选（15 分钟吸附，Alt 为 5 分钟）或单击（1 小时并裁剪到所在空白）后，选区旁弹出补录面板：时间可直接输入，搜索框自动聚焦，单击工作项即保存；⌘/Ctrl 单击可多选，一次添加多项并行记录。
- 没有重叠时不出现任何方式选项，静默按 GAPS 提交。与已有记录重叠时才显示“只填空白 | 并行均摊 | 覆盖”，默认只填空白；所选时段已全部有记录时默认并行均摊并禁用只填空白；重叠记录都不可修改时禁用覆盖。下方实时说明各方式的效果。
- 点击记录在原位编辑起止时间、更换工作项、删除（二次确认）；并行时可“独占此时段”，等于对该项该时段执行 REPLACE。运行中、跨日的一侧和不可编辑记录只读并说明原因。
- 拖动记录主体移动、拖上下边缘拉伸，松手即保存，失败回滚。拖动只能停在“开始拖动时未与之重叠”的相邻记录之间，同一工作项的其他记录总是障碍，因此拖动不会制造新的并行。
- 侧栏列出今天已记录和“最近与我的”工作项。“＋”提供 0.5h、1h、2h、4h 和自定义时长，悬停即在时间线上虚线预览，点击后从上班时间起依次排入空白，可跨多段，最多 20 段，排不下时提示剩余时长。桌面浏览器可把工作项直接拖到时间线，在落点生成 1 小时并裁剪到所在空白；触屏改用单击和“＋”。
- 计时日志的手动添加表单使用同一套重叠控件和默认值。

“按时长补录”对话框、抽屉和固定的三选一单选随之删除。

### 改归属

`POST /me/time-sessions/{sessionId}/reassign` 要求该记录的 If-Match，在 fill 的同一锁顺序和事务内软删除原记录，再按 PARALLEL 在目标工作项补同一时段，只跳过目标项自身已有的部分。沿用 deleted 与 added 事件，新记录为 MANUAL。没有选择原地 PATCH 换工作项，因为那样原工作项收不到移除事件，活动投影会出错；也没有给 fill 增加待删列表，以免把单条记录的版本校验混进不要求 If-Match 的批量补录。

### 计时器开关与上班时间

`work_item_timer_state` 增加 `timer_enabled`（默认 true）、`workday_start_minute`、`workday_end_minute`（默认 540、1080），通过 `CurrentTimeTracker.preferences` 返回，`PUT /me/time-tracker/preferences` 以计时状态 ETag 保存。偏好与计时状态共用用户状态锁和版本号：关闭时在同一事务内停止本人全部运行计时，关闭后 start、switch 返回 409 `TIMER_DISABLED`，stop 与 stop-all 仍可用。代价是保存偏好会让其他窗口进行中的计时命令以 412 刷新重试。

计时器关闭后，Web 隐藏右下角入口并忽略打开事件，工作项表格不再显示启停按钮（该项仍在运行时除外），首页计时卡改为“记录工时”进入今天，项目工作项工具栏隐藏“小计时器”。桌面状态增加可选的 `timerEnabled`：关闭时主进程不再自动弹出悬浮球，`show` 改为打开主界面，托盘与快捷面板去掉继续、查找、显示方式和置顶；旧版桌面壳不认识该字段，由 Web 调用 `hide()` 兜底。Web 按浏览器缓存最近一次的开关，避免计时入口在首次轮询前闪现，退出登录时清除。

上班时间只用于空白提示、按时长排入的起点和打开时的滚动位置，不参与统计、提醒或加班口径。每日标准工时取公司日历：`TeamTimesheetDay.standardMinutes` 新增，日页面进度和月历格的填满程度使用它，非工作日回退为 8 小时参考值。

计时候选的“最近”改为包含手动补录，否则只手动填报的人在侧栏和补录面板中只能看到分配给自己的工作项；`recentItems` 与 `resumeItems` 仍只看计时器会话，因为它们驱动“继续”。

## Alternatives considered

- 保留抽屉，只简化侧栏表单：月历上叠放的窄抽屉无法同时容纳时间线、工作项列表和就地编辑。
- 日视图作为“我的工时”的默认页：用户选择保留月历作为入口。
- 重叠时默认并行均摊：手动填报的重叠多数是拖过头，默认并行会悄悄改变已有记录的计入时长。
- 每次重叠都强制选择方式：多一步确认，且大部分情况答案相同。
- 计时器开关只存浏览器：Web、桌面与不同浏览器之间不一致，服务端也无法拒绝其他入口的开始。
- 独立的偏好表：关闭计时器需要与停止计时在同一锁内完成，另建表还要再定一套锁顺序。

## Consequences

日页面的空白、均摊、布局和吸附都在前端计算，并以服务端规划器为准；客户端预览与服务端结果不一致时，以保存后的重新加载为准，并提示跳过的时长。拖动和就地编辑使用既有 PATCH，若拖动期间其他窗口改动了相邻记录，仍可能产生并行，由服务端按 1/N 计入。

计时器关闭会停止全部运行计时，保留已记录的会话、报表与统计，同时隐藏入口并拒绝新的计时；重新开启只恢复入口，不自动恢复已停止的计时。桌面需要随本次发布更新才能完全隐藏托盘入口，旧版桌面仅隐藏悬浮窗。偏好保存推进计时状态版本，属于用户状态锁上的少量额外冲突。

## Verification

`pnpm run check:openapi`、OpenAPI 兼容检查（对 `origin/dev` 基线）、`pnpm run validate:event-contracts`、`pnpm run test:architecture`、`pnpm lint`（0 error）、`pnpm typecheck` 与 `pnpm build` 通过；API client 16 项、Web 1155 项、Desktop 93 项测试通过。后端单元测试 604 项通过（1 项既有符号链接用例在 Windows 跳过）。集成测试中 `TimeTrackingHttpIT`、`WorkItemHttpIT`、`DashboardHttpIT`、`ProjectStatisticsHttpIT`、`ProjectPurgeIT`、`ActivityProjectionIT`、`YumpooServerApplicationIT` 共 90 项通过；本机内存不足导致全量集成测试进程崩溃，其余集成测试未在本机复跑，以 CI 结果为准。

反馈判断同时检查 `createdCount`、`changedCount` 和 `deletedCount`，独占操作使用独立于补录的提示。新增组件回归覆盖仅删除重叠记录、裁剪或拆分重叠记录、没有实际变化，以及覆盖补录仅删除和只填空白无变化；相关 Web 定向测试 35 项、桌面计时器测试 27 项、`TimeTrackingHttpIT` 13 项均通过。HTTP 回归确认独占已有目标记录可以只删除其他记录，关闭计时器会停止跨项目的全部运行计时，重新开启不会自动恢复。

本机联调完成拖选即选即录、重叠时的方式控件与默认值、记录弹层的时间修改与删除确认、侧栏按时长排入与预览、拖动拉伸与移动及相邻记录夹取、从侧栏拖入时间线。执行 V78 的隔离 PostgreSQL 与后端联调确认：A 改归属到 C 后当天合计仍为 1 小时；独占后删除 B、保留 C 的完整 1 小时并正确提示；关闭计时器停止两项运行计时、隐藏 Web 入口及真实 Electron 计时器窗口，重新开启后运行数仍为 0。桌面联调使用生产计时器控制器、preload 与渲染页面组成的独立启动器；托盘操作的实点验收仍不在此次结果内。
