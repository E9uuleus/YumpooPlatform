# Agent Note: 项目工作项字段分组与独立分页

Status: implemented

## Problem

项目总表需要按工作项字段形成可折叠表段，同时保留单元格编辑、根项草稿、勾选、列布局、滚动位置和子表输入。仅对已加载的一页数据分组会遗漏分组和数量；先下载全部工作项会使大项目加载成本随总量增长。Element Plus 展开行的外层数组按位置匹配，插入表段标题会重建子表，单独设置工作项 row-key 不能保护其中的草稿。

## Decision

[项目总表](../../../../frontend/web-app/src/views/projects/ProjectOverviewView.vue) 保留一个 ElTable，把标题、重复表头、留白、加载入口以及子表容器建模为独立展示行。真实行以工作项 ID 标识，子表容器以父项 ID 标识；子表内容和单元格仍复用原组件。折叠使用展示样式隐藏表段，保留实例与输入。展示行不进入 tableItems、勾选结果、行菜单、拖拽锚点和写接口。

单字段分组支持处理人、状态、优先级、工作项类别与截止日期。只有根项参与分组和计数，子项跟随父项。标签与类别沿用目录颜色和排序，停用但仍有记录的标签保留；处理人按稳定用户 ID 记忆色板分配，新增成员不会重分配已有颜色。日期使用企业时区和周一起点，先划分今天、明天，再划分本周稍后、下周、更晚、已过去，空值在任何排序下置底。“已过去”只表达日期关系，不替代完成状态决定的业务逾期。复用分钟时钟与焦点恢复事件跨午夜更新。

[分组加载器](../../../../frontend/web-app/src/components/projects/useWorkItemGrouping.ts) 遍历筛选选项接口的全部游标获取完整数量。每组独立保存列表游标、加载状态和错误；只对可见表段及其附近加载工作项。分组查询与当前筛选取交集，分组顺序只改变表段顺序，组内排序仍由现有列表接口承担。版本与 AbortController 隔离切换前后的请求，失败保留当前内容并允许局部重试。

列表契约兼容增加可选 emptyField=ASSIGNEE|PRIORITY|DUE_DATE，服务端以 IS NULL 和原谓词相交，并写入游标查询指纹。省略该参数保留原指纹语义，无数据库迁移。日期组通过日期范围相交查询。字段、分组顺序、空组开关、折叠状态及处理人配色按账户、企业、项目存为本地偏好，不写入共享默认视图。

组内拖拽、置顶和置底只使用本组可见锚点，禁止跨组拖拽，禁止把分组结果保存为全局手工顺序。草稿留在发起行下，保存成功按实际字段归组；字段编辑成功后重算组归属和完整数量。

## Alternatives considered

- 每组建立独立 ElTable：列布局、滚动与勾选需要重复协调，跨组移动还会重建编辑组件，因此保留一个表格和稳定展示行。
- 下载全部工作项后分组：大项目启动成本不可控。改为完整分组元数据加可见组独立分页。
- 只对已加载页分组：会显示错误数量并遗漏后续页中的分组，不能作为正式语义。
- 继续使用 Element Plus 的展开行槽：外层按位置匹配导致子表在插入标题时重建。改为稳定父项 ID 的展示行，不修改第三方表格内部实现。
- 为每组增加数据库顺序或持久化分组：当前需求是单用户展示偏好，继续复用项目顺序与字段真源，避免新增顺序双真源。

## Consequences

分组元数据成本随不同字段值数量增长，不随全部工作项行数增长。组内分页按需推进；为保护已经选中、正在编辑或展开子表的远处根项，刷新时可能继续加载到对应行。显式置底需遍历目标组以获得真实末尾锚点，这是现有顺序接口的取舍，普通浏览不下载全部工作项。

数量查询与列表查询不是同一数据库快照，其他成员的并发编辑可能暂时导致数量与已加载行不一致；本地成功编辑、筛选变化与重新加载会校准。当前浏览器保留已浏览页以保护编辑状态，尚不对已加载表段做卸载虚拟化。

此决策与[类别目录决策](2026-09-02-work-item-category-catalog.md)互补：类别继续只是项目字段目录，不恢复 Content 独立视图。现有活动记录不被替代，无归档操作。

## Verification

规则测试覆盖空值、停用标签、颜色稳定性、周界与跨年日期；加载器测试覆盖超过 100 个分组、独立分页、请求失败、切换取消、偏好隔离与日期更新。页面回归检验同一主表与子表实例、勾选和草稿在分组及折叠切换后保持。后端 HTTP 集成测试在真实 PostgreSQL 中检验空值筛选交集和游标隔离。
