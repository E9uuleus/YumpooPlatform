# Agent Note: 讨论内嵌图片与附件文件卡片

Status: implemented

## Problem

描述已经支持截图，但发布、编辑与回复讨论只能保存文字。草稿讨论尚无 ID，不能用讨论聚合创建附件意图；正文净化器又明确裁剪图片和相对链接，单纯在编辑器增加入口无法形成可靠的保存与再次编辑体验。

## Decision

本 Note 部分替代[讨论编辑器](2026-09-05-work-item-discussion-composer.md)的图片白名单与附件入口范围，并扩展[富文本描述](2026-09-25-work-item-rich-description.md)的共享附件净化与上传机制。分页、Mention、ETag、幂等、只读显示和描述命令规则继续由原 Note 持有。

Web 的发布、编辑和回复均允许图片内嵌与文件卡片，通过按钮、粘贴或拖入选取文件。`useEditorAttachments` 与描述共用附件意图、PUT、可用状态轮询、占位替换、移除和中止逻辑；附件以父工作项 `WORK_ITEM` 为 owner，不新增 owner、表或迁移。图片支持 PNG/JPG/GIF，单张最多 20 MiB；文件沿用 PDF/DOCX/XLSX/PPTX/MD/TXT/CSV/ZIP 白名单，单个最多 100 MiB，不支持旧版 DOC。服务端类型识别、宏、ZIP、完整性与下载实时鉴权仍由附件模块负责。

占位节点仅属于编辑器草稿，不从已保存 HTML 解析。进行中和失败但未移除的占位都阻止发布或保存；取消编辑、放弃草稿、切换工作项和卸载中止在途上传与轮询。图片或有文件名的附件卡片属于可提交正文，只有空白、结构或上传占位不能提交。完成上传后占位在撤销历史之外替换，避免撤销恢复已结束的上传。失败讨论提交仍保留正文与现有幂等键规则。

讨论与描述共用严格净化：`img[src,alt]` 的地址必须精确匹配同源 `/api/v1/attachments/{uuid}/content`，其他地址整体移除，alt 去空白并截断到 255 字符。文件卡片保存为 `<a data-type="attachment" href="/api/v1/attachments/{uuid}/content" data-size="12345">文件名.pdf</a>`；只有带附件标记且精确匹配此路径的 href 可作为相对链接，不加 `target`，大小仅保留 1–104857600 的整数。无效标记按普通链接处理，仅绝对 HTTP/HTTPS/mailto 可保留 href，不允许通过附件标记放行其他相对地址。描述中的 Mention 继续降级为文字。

纯图片讨论允许保存；其 `bodyText` 使用 `[图片]`，以保持工作项讨论领域对象、V35 数据库 CHECK 与既有 API 响应的非空约束，避免为了展示摘要引入迁移或响应兼容例外。收件箱对空的可见讨论摘要也显示 `[图片]`；没有扩大不可访问目标的展示。文件卡片的摘要来自文件名。事件继续只携带既有 ID、时间或长度元数据，不携带正文和文件名。

编辑器用 `AttachmentFile` 节点保存卡片的原始文件名、地址和大小，查看态从服务端净化正文安全生成扩展名徽标与格式化大小，不把展示派生 DOM 回写为正文。评论图片点击后打开 Element Plus 图片查看器，文件卡片链接直接请求附件下载端点。描述使用同一上传 composable，图片入口继续保持原有范围，但可保存和展示合法文件卡片。

## Alternatives considered

- 给草稿讨论提前创建 ID 或新增附件 owner：引入草稿聚合与生命周期，现有父工作项权限已覆盖下载需求，拒绝。
- 允许任意相对链接、图片 URL、Base64 或本地 blob 预览：扩大内容与部署信任边界，无法复用附件实时鉴权，拒绝。
- 上传期间仍允许提交，稍后改写正文：会越过讨论强 ETag、幂等和编辑权限，拒绝。
- 允许 `bodyText` 为空：需要修改领域对象、数据库与响应约束；`[图片]` 能直接提供符合用户预期的摘要，采用该方式。
- 为文件卡片存储完整展示 HTML：扩展名与大小是可派生表现，增加白名单与再次编辑复杂度，采用规范化锚点格式。

## Consequences

讨论删除或草稿丢弃后，已上传但没有正文引用的文件仍是工作项附件，与描述一致，等待后续附件清理策略处理。没有前端自动删除附件，避免删除仍被其他正文引用的内容。引用其他工作项附件时，正文净化不反向查询附件归属，下载端逐次鉴权仍防止内容泄露。回滚到不支持图片和文件卡片的编辑器或净化器会裁剪新增格式；OpenAPI 白名单说明、黄金样例、净化器和前端须同步演进。

## Verification

净化器测试覆盖讨论与描述的共享图片规则、纯图片摘要、附件标记与精确地址、大小边界、危险链接、属性裁剪、幂等和空占位拒绝。HTTP 测试覆盖纯图片发布、幂等重放、读取、编辑、回复以及图片和文件卡片混合正文。前端测试覆盖按钮入口、粘贴和拖入、父工作项归属、占位禁用提交、失败移除和取消上传、文件卡片往返、只读下载与图片查看器、收件箱摘要。

本次针对性验证通过：净化器 13 项、`WorkItemHttpIT` 27 项、4 个相关前端 spec 共 67 项；全量 TypeScript typecheck、lint（零 error）、OpenAPI lint/黄金样例/SDK 一致性与兼容、事件契约与兼容、工作区边界、Markdown 链接和活动及冻结 Note 校验均通过。浏览器中的真实上传与下载验收依赖移除扫描后的运行时集成，由后续集成验证完成。
