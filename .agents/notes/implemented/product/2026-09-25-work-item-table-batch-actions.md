# Agent Note: 工作项表格列切换与批量操作

Status: implemented

## Problem

隐藏列会让 Element Plus 重建右侧单元格；预挂载的处理人列表、目录编辑器与日期选择器放大了重建成本。标题列和添加列共同分配剩余空间，又使隐藏列后的标题宽度改变。

## Decision

主表所有业务列使用固定 `width`，只有添加列使用 `min-width` 吸收剩余空间。宽屏留白由添加列承担；子项表保留固定列宽。业务列仍按 `columnIndex` 复用，不改变列拖拽和排序依赖的 key。

显示列菜单独立维护本地勾选状态，经 `requestAnimationFrame` 加下一任务提交表格更新。提交后等待 Vue `nextTick` 并立即执行现有 `doLayout`；FLIP 在绘制前重新测量，只对视口内的列单元格播放 160ms 平移或淡入。分组模式读取第一个展开分组的列头行；减少动画、拖列和调宽时跳过动画，新测量前取消旧动画。

处理人、状态、优先级、类别和截止日期弹层只在打开时挂载。标签和类别编辑器用同步 `busy-change` 通知父级，保存期间保留弹层内容，保证关闭弹层后异步 `updated` 仍能更新目录；关闭不得重置保存中的草稿。

## Alternatives considered

- 继续让标题列弹性分配剩余空间：隐藏列会改变其它列宽，不满足稳定布局要求。
- 只延迟布局或只加动画：无法消除单元格重建时预挂载的内容，且延迟布局增加第二次跳动。
- 所有弹层无条件使用 `persistent=false`：关闭保存中的编辑器会丢失完成事件，因此仅在空闲时销毁。
- 改用字段作为列组件 key：底层单元格 key 仍包含列序号，不能避免重建，并会改变现有列拖拽契约。

## Consequences

宽屏标题不会自动拉宽，可手动调宽。开发模式 100 行、30 成员的 Chrome Performance 对比显示节点和主线程阻塞减少，但 Element Plus 整表更新仍有成本，动画不能替代进一步的表格渲染优化。
