# Agent Note: 工作项表格列切换、批量操作与勾选同步修改

Status: implemented

## Problem

隐藏列会让 Element Plus 重建右侧单元格；预挂载的处理人列表、目录编辑器与日期选择器放大了重建成本。标题列和添加列共同分配剩余空间，又使隐藏列后的标题宽度改变。

行菜单缺少复制入口，勾选结果没有批量处理入口；表格保留的行对象可能携带旧 ETag。只清空业务层 ID 而不清空 Element Plus 的 reserve-selection 会造成勾选显示与数量不一致。

批量新增工作项或子项后，处理人、状态等字段只能逐行修改。单元格弹层选中后不收起，会遮住下一个要编辑的单元格；处理人头像提示显示在上方且可进入，会遮住上一行的处理人。

## Decision

主表所有业务列使用固定 `width`，只有添加列使用 `min-width` 吸收剩余空间。宽屏留白由添加列承担；子项表保留固定列宽。业务列仍按 `columnIndex` 复用，不改变列拖拽和排序依赖的 key。

显示列菜单独立维护本地勾选状态，经 `requestAnimationFrame` 加下一任务提交表格更新。提交后等待 Vue `nextTick` 并立即执行现有 `doLayout`；FLIP 在绘制前重新测量，只对视口内的列单元格播放 160ms 平移或淡入。分组模式读取第一个展开分组的列头行；减少动画、拖列和调宽时跳过动画，新测量前取消旧动画。

处理人、状态、优先级、类别和截止日期弹层只在打开时挂载。标签和类别编辑器用同步 `busy-change` 通知父级，保存期间保留弹层内容，保证关闭弹层后异步 `updated` 仍能更新目录；关闭不得重置保存中的草稿。

单项和批量复制共用 `workItemDuplicate.ts`，先获取完整详情，再复制类别、标题、优先级、处理人、描述、备注、时间线、截止日期与时间。标题加“（副本）”并限制总长 300；处理人必须仍是有效成员且在职、账号启用，优先级必须启用，否则清空。类别停用或不可用时跳过该项并说明原因。主项和子项分别调用对应创建 API；子项保留原父项。创建后用原项作为前锚点放置到原项下方，显式排序时不调整手动顺序，放置失败只是警告，副本仍创建成功。

复制不带状态，遵守 D3 的初始状态创建规则；也不复制计时、讨论、关系、子项或附件列表。描述中的图片保留原同源附件地址，沿用[富文本描述 Note](2026-09-25-work-item-rich-description.md)的服务端约束：描述净化不校验附件归属，下载按原附件父对象的实时读取权限鉴权。

`WorkItemBatchBar.vue` 只展示状态和发出意图，执行逻辑由 `useWorkItemBatchActions.ts` 管理。项目页工作台 teleport 到 body，固定距底部 28px，复用内容区左界与抽屉 inset；嵌入模式在所属表格区域 sticky 贴底。表格尾部预留空间，数量包含主项与子项，工具栏与数量播报具备可访问性标记。

批量复制保留勾选，超过 20 项才确认。归档/删除统一确认，包含子项影响与跳过数，跳过无删除权限项；选中父子项时先操作子项。转换仅处理可编辑且真实 `subitemCount=0` 的主项，父项候选排除所有已选项。归档、删除、转换仅对成功项取消勾选。移动按主表、分组、同一父项的子项分别保持原相对顺序，使用同级未选项为锚点；无移动权限项跳过，显式排序禁用整组操作。移动失败不推进前锚点，复制和移动都保留勾选。

执行队列只保存 ID 与父项 ID，每次操作前从当前主表/子项数据重新解析权限与 ETag，写请求使用新的幂等键。逐项串行执行，停止会等待当前项完成；失败不阻止其它项，结束后汇总结果，统一调用一次 `onRelationsChanged`。筛选、分组方式、视图或项目切换同时清空主表/子项的内部 selection 与业务 ID；展开/折叠分组本身不重置选择。

批量修改不设单独入口：被编辑的行处于勾选集合，且勾选总数（主项与子项合计）不少于 2 时，处理人、状态、优先级、类别与截止日期的修改应用到全部勾选项；标题、计时、更新时间与连接列不参与。弹层顶部显示「同步修改已选的 N 项」复选框，取消后本次只改当前行；弹层内容挂载和卸载时都恢复为同步。截止日期的快捷清空按钮在批量状态下以标题说明同步范围，工作台提示「编辑已选行可同步修改」。

批量修改复用上述串行队列、ETag 重解析、幂等键、停止与汇总，调用既有单项接口，不新增后端批量端点。值已等于目标的项不发请求并计为成功。状态按每项 `availableTransitions` 与看板移动权限跳过；需要迁移说明时只询问一次，且只随需要说明的迁移提交。只改日期时保留各项时间，只改时间时保留各项日期并跳过无日期项。处理人选择器在批量模式下改为草稿：「添加」按原顺序追加，超过 20 位的项跳过；「替换」写入所选列表，空列表即清空；由「应用到 N 项」一次执行。每项成功后就地合并返回详情且不触发分组刷新，批次末统一刷新一次。修改保留勾选，执行期间锁定单元格编辑。

主表与子项表的处理人、状态、优先级、类别弹层受控，同一时间只打开一个，旧弹层迟到的关闭不清除新弹层。状态、优先级、类别选中即收起，目录编辑模式不受影响。处理人可多选，选择后保持打开，清空搜索并回到输入框；「完成」、Esc 与空搜索 Enter 结束选择。表格内头像提示显示在右侧，不可进入，300ms 后出现、离开即隐藏，选择器打开时不提示。

## Alternatives considered

- 继续让标题列弹性分配剩余空间：隐藏列会改变其它列宽，不满足稳定布局要求。
- 只延迟布局或只加动画：无法消除单元格重建时预挂载的内容，且延迟布局增加第二次跳动。
- 所有弹层无条件使用 `persistent=false`：关闭保存中的编辑器会丢失完成事件，因此仅在空闲时销毁。
- 改用字段作为列组件 key：底层单元格 key 仍包含列序号，不能避免重建，并会改变现有列拖拽契约。
- 并行批量写入、逐项刷新：增加版本竞争和界面跳动，采用串行操作与批次末刷新。停止不强行取消当前写请求，避免无法判断服务器是否已提交。
- 复用 el-table 保留的行对象：刷新后可能仍是旧 ETag，采用 ID 重新解析当前数据。
- 复制附件实体或递归复制关系/子项：扩大复制含义并引入跨模块事务和权限处理，本操作只复制列出的工作项字段。
- 在工作台增加字段按钮，或提供多字段批量编辑面板：入口更明确，但需要另一套选择器和面板；用户选择直接编辑已勾选的行。
- 新增后端批量更新端点：需要新的契约、锁顺序与事件策略；沿用串行单项命令，权限、版本与事件语义保持不变。
- 处理人选中即关闭，用「+」继续添加：优化单人场景，但与连续指派冲突，因此保持打开并提供明确的结束操作。
- 移除头像提示，或保持上方加延迟：前者在只显示首字时丢失姓名，后者仍会挡住上一行。

## Consequences

宽屏标题不会自动拉宽，可手动调宽。开发模式 100 行、30 成员的 Chrome Performance 对比显示节点和主线程阻塞减少，但 Element Plus 整表更新仍有成本，动画不能替代进一步的表格渲染优化。

副本的描述图片仍依赖原附件与原父项读取权限；未来附件清理策略如果删除原图，副本中的引用会失效。复制不创建附件所有权或独立保留义务，未来附件清理必须明确考虑这种跨工作项引用。

批量操作不是事务：成功结果不因后续失败回滚，失败、跳过和停止后未执行的项保持勾选。异步期间外部修改仍可能产生 412，客户端不重放旧命令；汇总失败并刷新当前数据后由用户重试。

勾选状态下编辑单元格会隐式批量修改。误操作风险由弹层提示、可取消的同步复选框、工作台提示和结果汇总缓解；勾选多项时只想改一项，需要先取消同步或取消勾选。
