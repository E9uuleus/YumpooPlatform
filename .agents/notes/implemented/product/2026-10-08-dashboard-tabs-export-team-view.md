# Agent Note: 仪表板标签栏、PDF 导出与团队视图

Status: implemented

## Problem

多个私人仪表板只能从标题旁的下拉切换，入口不明显。指标卡默认 3×4 网格，在常见分辨率下是扁长方形，数字会被标题栏挤出卡片。用户需要把仪表板按原布局和视觉导出为 PDF。公司管理者还需要查看成员工时和当前任务，但私人仪表板依赖手动连接项目，且只统计本人所在的项目。

## Decision

[DashboardTabs](../../../../frontend/web-app/src/components/dashboard/DashboardTabs.vue) 用页内标签栏替代标题下拉，标签按创建顺序排列，可以横向滚动。双击当前标签可重命名，“全部仪表板”弹层提供搜索，末尾 `+` 用于新建。路由仍为 `dashboards/:dashboardId?`，切换前沿用自动保存守卫，不增加新页面。

团队视图使用保留的路由 ID `team`，作为第一个固定标签，仅公司管理员可见。它不是私人仪表板，没有连接项目、组件或布局配置。页面工具栏用分段控件在成员工时和成员当前任务之间切换，同一时刻只显示一张表。页面不提供项目或成员筛选，始终统计全公司。非管理员访问 `team` 时重定向到默认仪表板。权限与数据边界见[团队视图管理员报表](../security/2026-10-08-admin-team-reporting.md)。

- **成员工时：** 按周（从周一开始）、月、季统计。点击工具栏的区间按钮，弹出与手动计时相同的日历（`TimeCalendar`），跳转到包含所选日期的周期。行是成员，列是公司时区的自然日；悬停时整行整列以亮蓝色调加深。周末与工时深浅只是视觉提示，不代表标准工时校验。表格只显示一位小数的小时数。点击当日工时数字，按项目分组列出当天的工作项，详情中的合计、项目小计和每条工作项显示 `2h 05m` 形式的时分，与计时器一样按整分钟向下取整，不足 1 分钟显示 `< 1m`。项目名颜色按项目 ID 从明亮的预设色板分配，同一周期内不同项目颜色不重复（超过 10 个项目时复用）；周期内的项目组合变化时，同一项目的颜色可能不同。详情中的工作项色条统一使用工作项表格未分组时的默认亮蓝（`#579bfc`），不跟随项目颜色。Excel 导出在浏览器生成，含“工时汇总”和“工时明细”两张表。导出范围是当前勾选的成员；未勾选时导出全部可见成员，“隐藏无工时成员”同样生效。
- **成员当前任务：** 统计待开始和进行中的工作项，多处理人分别计入。按处理人分组，组头的成员名按成员着色，并显示进行中/待开始比例条和逾期数。展开/收起按钮只在悬停或键盘聚焦时出现；触屏设备（`hover: none`）上始终显示。分组默认折叠，展开后分页加载。任务表的色条使用工作项表格的默认亮蓝，状态/优先级色块与工作项表格一致。工作项列只显示名称，不显示编号，悬停可看到完整名称。任务表最宽 1120px，大屏上工作项列约 590px，不会随屏幕变宽；最窄 760px，更窄时在分组列表内横向滚动。截止日期列的表头和值居中。点击任务进入项目工作项详情。
- **动效：** 切换两个页面时，新页面从对应标签一侧淡入。成员工时翻页后，可视区内的前 16 行从翻页方向滑入（WAAPI）；合计小时数和图例计数滚动到新值；周期标签平滑切换；单日详情和日历弹层淡入下移，详情中的项目和工作项依次浮入。成员当前任务的分组和任务行依次浮入，比例条从左展开，展开/收起通过 `grid-template-rows` 平滑过渡。动效在 `prefers-reduced-motion: reduce` 下关闭，数字直接显示终值。

新建指标卡默认 12 列下 3×7、6 列下 2×7。“恢复默认布局”的 4 张指标卡一行排列，在 1280–1600px 视口宽度下接近正方形。数字字号随卡片宽高缩放。已有仪表板的组件尺寸不做迁移。

PDF 在浏览器中生成：先在离屏位置用浅色主题、宽屏 12 列布局和与网格相同的 40px 行高、8px 间距渲染 A4 横向页面，再用 modern-screenshot 以 2 倍分辨率转成图片，最后由 jsPDF 合成。分页只落在没有组件跨越的行边界。为了少留空白，单页最多缩小到 0.8；单个组件超过一页时，整页缩小但不截断。首页包含名称、导出时间、连接项目和筛选摘要。导出直接使用当前已加载的统计结果，不重新查询。

导出依赖与 ExcelJS 都通过动态导入加载。桌面端通过受控保存通道写入文件，见[安全 Note](../security/2026-10-08-admin-team-reporting.md)。

## Alternatives considered

- 在全局侧栏或页内左侧列表展开仪表板：侧栏收起后看不到，左侧列表会挤占画布宽度。标签栏与项目页头的分区导航方式一致。
- 把团队视图做成私人仪表板的新组件或新的“全公司范围”：需要推翻私人仪表板“不走管理员旁路”的决策，配置会和角色耦合，降级后仪表板失效。按计时日期分桶也不符合现有按工作项属性统计的图表管线。
- 新组件只统计已连接项目：改动最小，但管理员看不到自己未加入的项目，不能满足公司视角。
- 浏览器打印或 Electron printToPDF：Web 和桌面行为不一致，需要打印对话框，GridStack 在打印宽度下还会重排。服务端无头浏览器渲染则需要额外的运行时、凭据传递和部署成本。
- 后端生成 Excel：需要新增服务端依赖，而数据已经完整返回到前端，所以在浏览器生成。
- 批量把已有指标卡改成新尺寸：会覆盖用户已经选择的布局，因此只改变新建组件和默认布局的初始形状。
- 保留项目/成员筛选：页面的定位是全公司视角，导出范围已经改由勾选成员控制，所以移除筛选。
- 保留自定义区间：周/月/季加日历跳转已覆盖常用场景，因此去掉区间选择器。
- 继续使用 `el-table` 树形展开：做不到行列十字高亮，也难以只用一个弹层，因此改为原生表格，并对冻结列使用 sticky。
- 工作项色条继续跟随成员或项目颜色：与工作项表格的默认亮蓝不一致，深色项目色板也让页面偏暗。区分成员和项目的任务交给成员名、项目名的颜色。
- 详情沿用一位小数小时：看不出具体分钟，不便与计时记录核对；表格单元格空间有限，所以仍保留一位小数。
- 给 `tbody` 加 key 来重播行入场动画：季度视图会重建约 2.7 万个单元格。改为只用 WAAPI 动画可视区内的前 16 行，不重新渲染表格。
- 用 `<Transition>` 包裹 `v-show` 切换的两个页面：离场需要等一帧，两个页面会短暂叠在一起。改为在 `.team-view` 上使用 CSS 入场动画，元素从隐藏变为显示时浏览器会自动重播。

## Consequences

PDF 是位图：文字不可选择，文件大小随页数增加；视觉与屏幕一致，但不跟随深色主题。导出前需要等图表首次渲染，大仪表板会生成多页。团队视图的范围、权限、统计口径和私人仪表板相互独立，两者的数字不保证一致。新增依赖 jspdf、modern-screenshot、exceljs 均为懒加载分块，并在 `allowBuilds` 中禁用 core-js 的安装脚本。

本记录补充[私人仪表板](2026-09-16-personal-dashboards.md)中“后续导出需要重新明确口径”的约定：PDF 导出沿用当前组件的统计结果与权限交集，不新增接口。

## Verification

首次交付时，前端测试覆盖标签栏选择与重命名、PDF 分页与缩放、周期计算、工时矩阵聚合，以及 Bug 修复后下钻只显示所选项目。DashboardHttpIT 在真实 PostgreSQL 中验证管理员权限、跨自然日拆分、逾期与未分配统计、任务分页和区间校验。浏览器中实测了标签栏、项目工作量下钻、两页 PDF 的内容与版式、季度 92 列横向滚动、任务展开、深色主题和 375px 宽度。XLSX 的两张表、冻结窗格、合并单元格和自动筛选也已检查。

团队视图重设计时依次执行 `pnpm --filter @yumpoo/web-app exec eslint --fix src/components/dashboard/team src/components/timer`、`pnpm --filter @yumpoo/web-app lint`、`pnpm --filter @yumpoo/web-app typecheck` 和 `pnpm --filter @yumpoo/web-app exec vitest run src/components/dashboard src/components/timer src/design-system`。全部通过；lint 为 0 个错误、1363 个既有格式警告，28 个测试文件的 389 个用例通过，包含手动计时日历、工时聚合、Excel 构建和任务刷新回归。

通过 `pnpm dev:web`、项目本地管理员和临时 PostgreSQL 17 数据库进行浏览器验收，使用 5 位成员、3 个项目、56 个当前任务及 11 条计时记录。实测了分段切换后的勾选状态保留、周/月/季切换与左右翻页、日历选日跳转、行列悬停高亮、按项目分组的单日明细及重复点击/外部点击/Esc 关闭。任务默认折叠，展开先加载 50 条，“加载更多”后显示完整 52 条，任务链接进入对应工作项详情。季度 92 列横向滚动时前三列保持冻结，纵向滚动时表头和底部合计保持固定；深色主题可正常显示。

实际下载并检查了三份 XLSX：勾选导出的汇总表仅含所选 2 位成员，未勾选时汇总表包含全部 5 位可见成员，隐藏无工时成员后汇总表仅含 2 位有工时成员。各文件均包含“工时汇总”和“工时明细”，明细成员范围与对应导出范围一致。

评审修复时，列悬停改为直接切换单元格样式，不再触发整表重渲染。在 300 位成员、92 列的季度视图中，单次跨列更新从约 256ms 降到约 2.4ms。加载遮罩改为挂在不滚动的外层，横向或纵向滚动后刷新仍覆盖可视区域。键盘切换视图时会关闭单日明细和日历弹层。以上用模拟接口数据在浏览器中实测；lint、typecheck、verify-agent-notes 和上述 vitest 范围均通过，新增断言覆盖 `shortHours`、`dayBreakdown` 和 `projectColors`。

本轮调整了配色、时分详情、悬停展开按钮、工作项列和动效，执行了 `pnpm --filter @yumpoo/web-app exec eslint --fix src/components/dashboard/team`、`pnpm --filter @yumpoo/web-app lint`、`pnpm --filter @yumpoo/web-app typecheck`、`pnpm --filter @yumpoo/web-app exec vitest run src/components/dashboard src/components/timer src/design-system` 和 `pnpm verify-agent-notes`。新增断言覆盖 `hoursMinutes` 的取整与格式，以及任务行只显示名称。浏览器验收使用挂载真实 `TeamDashboard`、拦截团队报表接口的临时页面（未提交），实测了：
- 单日详情显示 `5h 12m` 等时分，工作项色条为 `rgb(87, 155, 252)`；
- 只有悬停行显示展开按钮，展开后按钮旋转 90°；
- 截止日期表头和值的水平偏移均为 0；
- 1440 和 2560 宽度下工作项列均为 593px；
- 375px 宽度下工作项列保持 233px，分组列表横向滚动，页面不横向溢出；
- 翻到下一周期时行从右侧滑入；
- 加载更多后新增行的入场序号从 0 重新计算；
- 深色主题显示正常，控制台无错误。

在 300 位成员、92 列的季度视图中，列悬停单次约 4.1ms，与改动前的 4.3ms 持平；翻页总耗时与改动前相当，主要耗在模拟数据生成上。
