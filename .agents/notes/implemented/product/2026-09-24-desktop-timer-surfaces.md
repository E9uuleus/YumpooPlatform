# Agent Note: 桌面计时紧凑界面、快捷面板与显示偏好

Status: implemented

## Problem

176 像素的悬浮球即使缩到 128 像素仍占据桌面，缩放手柄、名称气泡与侧边详情叠加后入口分散。托盘右键是系统原生菜单，悬浮球右键落在原生拖动区域只会弹出 Windows 窗口菜单，工作项窗口又是另一套样式，三处视觉与操作不统一。置顶与尺寸只保存在进程内，重启后需要重新设置，也没有贴边等更省空间的显示方式。

## Decision

紧凑界面提供悬浮球与侧边栏两种显示方式，与工作项窗口、快捷面板共用 `styles/timer-surface.css` 中由主题令牌派生的 `--yp-timer-*` 表面、发丝线、分层阴影与芯片色，随 Light、Dark、Night 切换。`useAppearance` 监听 `storage` 事件，主窗口切换主题后计时窗与面板实时同步。

悬浮球提供小、中、大三档（56/64/80 像素）。静止时圆面显示细圆环与时长：不足一小时为 `mm:ss`，满一小时为 `1h25`，避免误读为分秒。计时中圆环按当前分钟扫过，暂停静止，保存后转绿并显示勾选，断线显示琥珀点。开始/暂停按钮位于圆面内：指针进入或键盘聚焦时，时长缩小淡出，按钮以带回弹的缩放旋转入场，离开后换回时长；没有可计时工作时按钮常驻，代替时钟图形并打开工作选择。悬停 350 毫秒后向屏幕空余一侧展开 216 像素胶囊，与球连成一体，显示标题（可打开工作项）、项目与本次时长，以及更换工作；离开球体和胶囊 250 毫秒后收起。缩放手柄与名称气泡移除，大小改由设置选择。

侧边栏是贴在屏幕边缘的 32×112 标签：顶部是与悬浮球同源的小进度环（计时中为脉动点，暂停、保存、未开始分别显示对应图形），下方以“数值 + 单位”纵向排列时长（不足一小时为分/秒，满一小时为时/分），未开始时竖排显示“开始计时”；计时中贴屏幕边缘的一侧亮起细光条。悬停滑出 288×152 卡片，包含类别图形、标题、项目、`HH:MM:SS`、暂停/继续、状态与更换工作。标签与卡片可沿边缘拖动：拖动期间离开屏幕边缘 6 像素，补全四边边框与圆角；Windows 原生拖动结束后按标签中心吸附到较近一侧、恢复贴边样式并保存纵向比例。

工作项窗口内容区为 360×480，窗口四周另留 12 像素透明阴影边距。头部齿轮打开设置视图：显示方式（带示意图的悬浮球/侧边栏卡片）、悬浮球大小或停靠位置、窗口置顶，修改立即生效并由主进程保存。`TimerWindowMode` 增加与选择器同几何的 `settings`，托盘与快捷面板可直接打开设置视图；Ctrl+K 聚焦搜索，Esc 从设置返回。

托盘右键与紧凑界面右键打开同一自绘快捷面板：状态卡（当前或最近工作、实时时长、暂停/继续）、查找工作项、打开主界面、显示方式分段（悬浮球/侧边栏/隐藏）、窗口置顶、设置与退出。面板是独立透明弹出窗口（`toolbar` 类型、`pop-up-menu` 层级），在主 renderer 首次发布状态后预热并加载 `/timer/menu`。Web 入口对该路径单独挂载 `TimerQuickMenu`，不加载路由、会话和计时轮询，只渲染主进程推送的 `TimerMenuState`，因此未登录时也可使用。托盘面板贴近任务栏所在边（由工作区与显示器边界推断，自动隐藏任务栏按底部处理），紧凑界面面板在光标处打开并在越界时翻转。面板获得焦点后失焦即隐藏；打开时记录当时的焦点窗口，面板未能取得焦点时，焦点离开该窗口也会关闭面板；紧凑界面开始拖动时关闭面板。250 毫秒内再次右键托盘视为关闭；打开时聚焦面板容器，方向键与 Home/End 进入菜单项，Esc 关闭。面板未加载、加载失败或渲染进程退出时回退到条目一致的原生菜单。拖动区域右键拦截 `system-context-menu` 并始终阻止系统窗口菜单，按钮区域右键使用 `webContents` 的 `context-menu`，仅紧凑模式响应。

面板动作经 `yumpoo:timer:menu-action` 的封闭枚举交给主进程执行，只接受面板窗口主框架。暂停/继续复用既有 `dispatchCommand` 交给主 renderer，主进程依据自身状态决定停止的会话或继续的工作项，不接受 renderer 传入标识。`yumpoo:timer:preferences` 只接受主窗口、计时窗与面板窗口主框架提交的 `display`、`orbSize`、`dockSide` 合法枚举。面板时长使用主 renderer 发布的可选 `clockOffsetMs`（绝对值不超过 7 天的整数毫秒）与服务端时钟对齐。圆面内的按钮不能是原生拖动区域，因此计时窗可调用 `yumpoo:timer:drag`（仅布尔值，仅计时窗主框架）：按下后移动超过 4 像素即由主进程按光标位置移动窗口，松开时结束并吸附，这次点击不触发启停。主进程经 `yumpoo:timer:dragging` 通知渲染端拖动开始与结束。

偏好保存在 `userData/timer-preferences.json`，格式为 `{version: 1, display, orbSize, dockSide, dockY, pinned}`，默认悬浮球、中号、右侧、垂直居中、置顶。启动时同步读取，超过 4KB、JSON 损坏或版本不符回退默认值，字段逐项校验；写入先写临时文件再重命名，并串行执行。

几何集中在 `desktop/desktop-shell/src/main/timer-geometry.ts` 的纯函数中。原生形状同时裁剪绘制，因此所有表面在形状内保留 10 像素阴影边距。悬浮球窗口左右各预留至多 216 像素透明画布，形状在收起时为圆、展开时为胶囊，均按像素行生成；侧边栏窗口贴边，形状为标签或整张卡片。胶囊与卡片开关只改变形状、不移动窗口；原生形状先扩大再渲染胶囊，胶囊离场过渡结束后再收缩。悬停轮询直接对当前形状做命中测试。拖动由 `will-move` 或按钮拖动开始：拖动期间冻结悬停。悬浮球始终单独拖动：胶囊不属于拖动区域，已展开的胶囊在拖动开始时由原生形状立即裁掉并收起，拖动中和放下后都不再展开，直到指针离开一次；侧边栏卡片未展开时同样保持收起，已展开的卡片随拖动保持。页内悬浮球按下拖动时同样收起胶囊。Windows 在原生拖动结束的 `moved` 事件重新约束画布并吸附，其他平台以 120 毫秒防抖的 `move` 结束拖动。

Web 远程部署、桌面壳单独安装，两者版本可能不一致。新增桥接方法均为可选，Web 在缺少 `setPreferences` 时隐藏齿轮；新主进程忽略旧 Web 发送的 `size`/`titleVisible`，缺少 `clockOffsetMs` 时按 0 处理。发布顺序为先 Web 后桌面壳。

本记录部分取代[计时窗与托盘决策](2026-09-08-timer-work-picker.md)中的悬浮球尺寸与缩放、名称气泡、侧边详情、原生托盘菜单，以及置顶和尺寸只在进程内保留的内容；候选、命令路由、退出握手与保存反馈仍由该记录负责。

## Alternatives considered

- 只缩小原球并保留缩放手柄：节省空间有限，手柄与名称气泡仍分散入口。
- 常显 `HH:MM:SS` 与按钮的计时胶囊：信息直接，但失去球形识别；改为悬停时从球体展开胶囊。
- 只露出细条的贴边隐藏：最省空间，但不悬停时看不到时长。
- 原生菜单加图标：无额外进程，但外观由系统决定，无法与计时窗统一；保留为回退。
- 在计时窗透明画布内绘制右键菜单：托盘菜单需要贴近任务栏，与球体位置无关，还会扩大计时窗画布与形状管理。
- 面板加载完整应用并自行轮询计时：首次打开慢，并重复鉴权与轮询；改为主进程推送状态。
- 偏好存入 `localStorage`：桌面 partition 不持久化，重启即丢失，且主进程在 renderer 加载前就需要决定窗口几何。
- 用 `tray.getBounds()` 定位面板：图标位于隐藏溢出区时不可靠。
- 开始/暂停按钮只放在胶囊里：圆面整体可原生拖动，但暂停需要先等胶囊展开；改为悬停时按钮替换圆面时长，并用按钮拖动接管保持整球可拖。
- 按钮常驻圆面：一眼可操作，但常态看不到时长，也更容易在拖动时误触启停。
- 只依赖失焦关闭面板：从悬浮球右键打开时，面板可能拿不到焦点，点击别处后无法关闭。

## Consequences

预热面板多占一个渲染进程（约 50–80MB），并解析一次完整 SPA 包；如需优化，可为 `/timer/menu` 增加独立 Vite 入口，nginx 与 IIS 的 SPA 回退已覆盖该路径。置顶从进程内状态改为持久化。侧边栏只记录纵向比例，重启后回到主显示器；Linux 没有 `moved` 事件，吸附依赖防抖，可能在拖动停顿时发生。Windows 可能拒绝弹出窗口获取焦点：从悬浮球或侧边栏打开时依靠焦点离开打开者关闭；从托盘打开且没有任何本应用窗口获得焦点时，只能由 Esc、再次右键托盘或面板动作关闭。按钮拖动由主进程约每 16 毫秒读取光标并移动窗口，最长 60 秒自动结束。阴影边距使可点击区域略大于可见区域。Web 页内浮窗与画中画共用新的光环球与 360×480 面板，但不提供设置与侧边栏。
