# Agent Note: 工作日历、加班统计与工时异常提醒

Status: implemented

## Problem

团队视图写死周末，无法识别法定节假日和调休补班。V6 日历覆盖表只有只读端口，没有管理员写入口；团队视图也没有加班统计和异常工时提醒。

## Decision

其中提醒入口归一化到工作台团队视图的目标由[团队审阅模块](2026-10-13-team-review-module.md)部分替代。

日类型增量新增 `HOLIDAY` 表示法定节假日，保留 `NON_WORKDAY` 表示休息日。未显式设置的日期按周一至周五工作、周末休息，工作日标准工时可继承公司默认值。

管理员按年度整体替换全部显式日期，未列出的日期恢复默认规则。V74 的 `company_calendar_year` 保存年度版本，HTTP 通过 If-Match 做乐观并发控制，并写入年度替换安全审计。年度替换在同一事务内批量写入日期。管理响应保留解析后的 `standardMinutes`，另以 `configuredStandardMinutes` 返回原始工作日设置，空值表示继承；编辑回填只使用原始设置，避免保存后固定公司默认工时。`source` 保留每个日期的 `MANUAL` / `IMPORT` 来源，导入草稿标记 IMPORT，手工修改的日期改为 MANUAL，未编辑日期保存时保留来源。

浏览器解析 xlsx，导入结果先写草稿；错误行保留原草稿，下载模板同时导出当前显式日期。富文本取文本，公式只读取已有缓存结果，不计算公式；无缓存及 Excel 错误均按行、列提示。工时换算为分钟后须满足 1–720 的写入约束。服务器不解析文件。

加班只统计非工作日（休息日和法定节假日）的全部计时工时，工作日超时不计入。团队视图复用既有工时矩阵的非工作日列，成员、工作项、每日和整体合计都由保留的列重新计算；Excel 复用既有工时版式。某日缺少日历响应时按默认周末规则判断，列头、筛选及导出共用同一列模型。

`WORK_HOURS_ANOMALY` 复用 [ScheduledJob 框架](../architecture/2026-10-12-scheduled-jobs.md)，默认停用，由管理员配置执行时间。任务以计划时刻 triggerKey 和公司时区推导首个检查日（计划日前一天），逐自然日补查至实际执行时的昨天，避免停机后调度器推进执行时间而漏掉中间日期；不检查尚未结束的今天。使用与团队视图相同的原始计时切分和 ACTIVE 项目范围。默认阈值为 12 小时，超过阈值才产生异常；V75 通过公司、成员、工作日唯一键保证每人每日最多一次，并在同一事务发布 `reporting.work_hours_anomaly_detected` v1。

catalog 的 `listForScheduler` 和 workitem 的 `timeEntriesForScheduler` 是无 actor 的系统作用域公开端口，只供定时任务使用，结果不经 HTTP 返回。HTTP 报表的管理员授权边界仍由原公开端口执行。

独立消费者 `notification-work-hours-v1` 只向有效公司管理员（含 APP_MANAGER）发送 `WORK_HOURS_ANOMALY`，接收前再次与 ACTIVE/ENABLED 账号求交集。V76 的 `MEMBER_DAY` 目标不引用项目，保存成员、日期、时长和阈值；新事件没有历史积压，不设独立投影水位。该原因不归入任何分组，只出现在未读/全部并计入总数；读取时仍需 COMPANY_ADMIN 才返回目标数值。Web 点击提醒跳转到团队视图对应日期所在周期。

提醒入口 `/dashboards/team` 由既有会话路由守卫归一化到当前用户的工作台团队视图，保留日期参数；仪表板继续使用工作台规范地址。

## Alternatives considered

- 把 `NON_WORKDAY` 改名为 `REST_DAY`：会扩大迁移和既有测试改动，保留原值。
- 内置或联网获取法定节假日：内置需要逐年发版，次年安排通常年末才公布，采用管理员维护与 Excel 导入。
- 准实时检查：用户选择每日检查前一自然日，复用已存在的调度和 Outbox。
- 提醒发给本人或项目负责人：用户明确选择只发给有效公司管理员。
- 新增通知分组：会增加筛选和计数契约，保持既有分组集合。
- 将工作日超时计入加班：用户选择仅统计非工作日工时。
- 在后端另算加班汇总：前端已有完整逐日数据，复用矩阵过滤与导出。

## Consequences

加班统计实时计算，修改过去日期会改变历史统计；未设置的年份始终按默认周末规则。已发出的异常提醒不撤回或重算，每人每日唯一键也不因阈值变化而重置。桌面壳的原因能力过滤使该提醒只在 Web 收件箱展示，不弹出托盘提醒。

响应枚举扩展使用精确 OpenAPI 例外 `2026-10-12-work-hours-anomaly-notification`。例外绑定最新 dev 基线与最终规范的完整 SHA-256；仅去掉两个新增通知枚举的临时规范须先通过完整 openapi-diff，其余契约变更保持兼容。
