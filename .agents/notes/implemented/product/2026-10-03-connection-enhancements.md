# Agent Note: 项目连接筛选与增强入口

Status: implemented

## Problem

连接列已经能够跨项目展示最小卡片，但表格只加载当前页，不能用当前页连接缓存准确筛选项目工作项。连接过滤若在分页后执行，会产生稀疏页面、错误计数及游标串用。

## Decision

项目列表与筛选选项接受 `connectedColumnIds`、`unconnectedColumnIds` 和 `incomingProjectIds`。前两者逐列取交集，入站项目选择沿用既有多选的并集语义；三组条件与其他字段筛选取交集。连接谓词在 SQL 使用 EXISTS / NOT EXISTS，先于计数和分页，规范化后的三个 ID 集合参与列表及选项游标指纹。没有增加连接排序或分组字段。

连接必须未解除、列未删除、对端工作项未删除；归档对端仍保留，与[最小卡片授权](../security/2026-09-30-connection-intake-and-card-visibility.md)一致。未连接筛选还要求列确实属于当前项目且有效，未知或外项目列返回空结果，避免把无效列解释为全项目匹配。入站项目选项按工作项去重计数，项目名称经 catalog 公开端口批量取得，不从 workitem 查询 catalog 表。

前端连接分组使用列目录与服务端 `INCOMING_PROJECT` 选项，入站来源分组显示为「双向连接来源」；同一列的已连接、未连接选择互斥。请求入站来源选项时仅去除 `incomingProjectIds` 自身，保留其他条件，避免选择 A 后无法再加选 B；列表请求仍携带完整并集条件。完整取得 UUID 游标的所有选项页后，仅在显示层按中文名称自然排序、同名按 UUID 排序，不改变服务端分页、游标或计数口径。

缺失的已选列和来源保留为可单独取消的行，不自动剔除 URL 条件。目录成功加载后缺失列显示为不可用；来源选项成功加载后缺失的已选来源显示计数 0，不将零匹配误作项目已删除。加载中、未加载或失败时显示待确认和未知计数，保留已有条件；旧路由的迟到响应不得覆盖新上下文。筛选保存在项目路由，可清除并用于表格、既有字段分组和看板列表请求；仪表板嵌入不显示或传递这些条件。连接列偏好仍由[表格体验](2026-09-30-connect-column-table-experience.md)拥有。

三个连接筛选数组在两个接口中均最多 20 项，与 `ConnectColumn.MAX_COLUMNS` 一致。服务端在去重前校验原请求长度，超出返回对应字段的 422 `TOO_MANY`，内部查询条件同样限定集合大小；前端达到上限后禁用新增但始终允许取消已选项。OpenAPI 声明 `maxItems:20`；此约束相对 dev 的新参数兼容，当前规范承接既有通知原因的精确兼容例外，详见[站内收件箱](../architecture/2026-09-25-notification-inbox.md)。

看板复用 A6 缓存批量加载当前泳道工作项的连接，标题下展示出站连接与[双向连接列](2026-10-04-two-way-connect-columns.md)的反向连接；合计最多三个 `ConnectionChip`，其余由 `+N` 打开按方向分组的只读连接列表。chip 打开已连接工作项卡片并重新请求连接，以当前权限决定是否能打开详情或编辑字段。看板卡片及溢出列表不提供新建或解除入口，不扩大服务端能力。工作项标题按钮与连接按钮为同级元素，避免嵌套按钮与点击冒泡误打开工作项抽屉。

## Alternatives considered

- 对已加载行的 A6 缓存做过滤：会遗漏其他页，无法给出完整计数，故在 SQL 先过滤。
- 用连接 JOIN 直接扩展工作项行：同一事项多个连接会重复计数和分页，故列表使用 EXISTS，入站选项按项目和工作项去重。
- 把其他项目或已删除列视为无连接：可能使失效筛选意外匹配全部工作项，故保守返回空结果。
- 静默移除 URL 中缺失的筛选 ID：会将已认可的空结果改变为其他结果，并可能把加载失败误判删除，故保留可取消行。
- 在服务端按项目名称改排入站选项：会改变现有 UUID 游标及分页稳定性，因此在前端取得全部页后排序。
- 增加新的连接权限或任意项目信息端点：已有卡片授权与 catalog 最小项目端口足够，不扩权限和公开字段。

## Consequences

连接数量不改变工作项查询基数。删除、恢复和归档后的筛选结果以当前可读连接事实为准。当前游标绑定查询条件，不承诺连接事实变化前后的数据库快照。

`ConnectionFilterIT` 覆盖列交集、入站去重、A/B 并集、计数、UUID 选项分页、游标、删除恢复、归档与不可见项目；`ConnectionHttpIT` 验证请求参数、三个数组在两接口的 20/21 项边界、去重前上限及服务端鉴权。前端组件与容器回归覆盖状态选择、选项去除自身筛选、分页后稳定排序、缺失项取消、路由恢复、加载失败、迟到响应及服务端计数。

`ConnectKanbanConnections` 与看板容器测试覆盖三个 chip、溢出只读列表、批量单元格请求及卡片打开隔离；卡片测试覆盖看板只读模式下仍重新鉴权且不可解除。
