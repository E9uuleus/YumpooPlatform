# Agent Note: 桌面收件箱徽标与最小文本提醒

Status: implemented

## Problem

主窗口收起后用户无法发现新的评论、提及、指派与项目成员变化。应用使用便携 Windows 包，不能假设系统已存在带 AUMID 的安装快捷方式；收件箱提醒也不能向桌面通知中心泄露工作项标题或评论正文。

## Decision

可选 `DesktopBridge.inbox` 接收账号、未读总数和至多五条最新未读引用。每条仅包含通知 ID、原因、操作者显示名与创建时间；主进程严格拒绝未知键、重复 ID、非法账号、计数、时间及原因。状态发布仅接受主窗口主框架，复用 `isTrustedAuthIpcSender` 校验窗口、框架和来源。偏好读取与设置另外允许受同一校验约束的快捷面板主框架，计时窗或其他 renderer 不能发布收件箱状态。

`InboxNotifier` 从既有应用图标位图运行时合成右上角红点，不增加品牌资源。托盘使用合成图标，tooltip 在计时标题之前追加未读数量，避免长标题截断数量；Windows 主窗口同步 `setOverlayIcon`，macOS/Linux 使用 `app.setBadgeCount`。收件箱入口及 tooltip 未读行仅在主窗口发布有效账号状态后出现，即使该账号未读数为零；未登录、旧 Web 未发布收件箱状态时保持隐藏。注销、主窗口关闭及渲染进程退出清除徽标、水位与待提醒队列，并恢复隐藏入口。

每次账号变化首先建立创建时间与同时间 ID 水位，首次不补弹积压；计数先到而列表尚未到时，继续等待列表建立基线。焦点窗口和关闭提醒偏好仍推进水位，恢复后不补弹。新提醒最多三条时逐条展示，超过三条时合并为“你有 N 条新通知”；总数增长超过五条载荷时，以增长数量和新引用数量的较大值显示。创建时间早于水位的旧未读重新出现不会提醒。

Windows 使用 `tray.displayBalloon` 且设置 `respectQuietTime`，不设置 AppUserModelId。每条 balloon 由自身十秒生命周期定时器或点击推进队列；`balloon-closed` 不推进，因为该原生事件没有通知 ID，点击后迟到的关闭事件无法区分属于前一条还是新一条。点击立即消费当前提醒、唤起主窗口并尝试推进；若主窗口已获得焦点，剩余队列按焦点抑制规则清除。定时器绑定提醒对象及账号代次，reset 同时取消定时器，防止旧回调消费新账号队列。其他平台使用 Electron `Notification`。单条仅显示操作者与“提到了你 / 回复了你 / 评论了你关注的工作项 / 给你指派了工作项 / 更新了你的项目成员身份”，不显示标题、正文或项目名。点击通过 `yumpoo:inbox:open` 发送通知 UUID；合并提醒发送 null 进入收件箱。账号代次防止旧通知回调跳进另一账号。

`InboxPreferenceStore` 单独保存 `userData/inbox-preferences.json`，格式 `{version:1,toasts:true}`。损坏、超大文件或版本不匹配回退默认；串行临时文件写入后重命名，不触碰计时偏好。快捷面板同一新增行提供收件箱未读数与“桌面通知”开关，原生回退菜单提供收件箱入口。面板高度由 356 增至 396 像素，宽度不变。旧壳无 `inbox` 契约时 Web 隐藏桌面相关控件，通知中心仍可作为纯 Web 功能运行。新偏好不通过会拒绝未知键的 `yumpoo:timer:preferences` 发送。

本记录补充[桌面计时界面与快捷面板](2026-09-24-desktop-timer-surfaces.md)，其计时显示、置顶、窗口几何与命令握手约定继续有效。

## Alternatives considered

- Windows 统一使用 `Notification` 并设置 AUMID：便携分发不保证系统快捷方式注册，提醒可靠性不足。
- 添加带红点的品牌图片：产生重复资产与打包维护成本，运行时合成即可复用应用图标。
- 首次同步补弹全部未读：登录和重启产生大量历史提醒，偏离“新通知”语义。
- 在系统提醒中显示业务标题或摘要：系统表面可能在锁屏可见，违反最小文本边界。
- 将开关追加到计时偏好：混淆功能所有权且旧通道拒绝未知键，因此独立持久化和 IPC。
- 点击后直接将后续 `balloon-closed` 解释为新提示关闭：原生事件没有关联标识，会跳过尚未读到的下一条；仅等待关闭事件又可能在 Windows 只发点击事件时卡住，因此使用提醒自身的有界生命周期。

## Consequences

桌面提醒使用主窗口轮询提供的摘要，不新增系统后台网络客户端；最新引用限制为五条，大批新增时只能合并。提醒偏好属于当前桌面安装而非服务端账号。按创建时间水位过滤意味着延迟出现且早于水位的通知只进入收件箱，不补弹。Windows 实际 balloon 展示与系统静默设置相关；用户关闭单条提醒后，未点击时下一条仍等该条十秒生命周期结束，不依赖系统关闭事件的顺序。macOS/Linux badge 支持由桌面环境决定。自动测试覆盖校验、伪造发送者、水位、抑制、合并、账号切换、reset、点击、迟到关闭事件、徽标像素及独立偏好；系统托盘实际显示、任务栏覆盖和多屏定位仍需真实 Electron 人工验收。
