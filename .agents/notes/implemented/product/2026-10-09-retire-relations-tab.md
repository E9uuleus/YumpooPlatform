# Agent Note: 下线关系页并在表格管理父子关系

Status: implemented

## Problem

详情抽屉的关系页把父子、相关、阻塞、来源和重复五类关系放在同一入口，父子管理与表格的根项和子项展示分散。当前产品只需要在表格内管理两层父子结构，因此保留独立关系页和四类普通关系编辑入口会增加不再需要的操作路径。

## Decision

共享详情抽屉只保留详情、协作讨论和动态。关系页及其跨项目跳转组件已经移除；旧链接携带的关系页参数按未知页签回退详情并被消费，仍可打开原工作项。

表格根项继续支持添加子项和转为子项；子项行菜单增加“移到其他父项”和“转为独立工作项”。换父复用同项目 `PARENT_CHILD`、`currentRole=CHILD` 候选查询，排除当前父项并允许携带 `activeParent` 的 `REPARENT_REQUIRED` 候选。提交使用 `activeParent.relationId` 和 `activeParent.etag` 调用原子换父命令，固定原因是“通过表格行菜单更换父项”。冲突时重新读取候选并保留选择器，重试使用新的关系 ETag。

转为独立工作项先确认，再读取当前工作项的父子关系，只解除 `currentRole=CHILD` 的边；使用关系自身 ETag，固定原因是“通过表格行菜单解除父项”。成功后刷新工作项、实际旧父项及新父项；行菜单同时使原表格父项缓存失效，以覆盖加载候选前其他用户已换父的情况。主表和已展开的受影响子表重新读取服务端事实。

本记录部分替代 [Work Item 单层父子关系与根查询语义](../data/2026-08-28-work-item-parent-child-relations.md) 中详情抽屉关系页的决定。两层模型、同项目父子约束、关系表、API、并发命令和审计事件继续由该记录持有；[跨项目关系授权与脱敏](../security/2026-08-31-cross-project-work-item-relation-visibility.md) 的后端约束也继续有效。相关、阻塞、来源和重复仅移除 Web 操作入口，既有关系数据、服务端接口和关系动态渲染保持兼容。

## Alternatives considered

- 保留仅管理父子的关系页：拒绝。会继续与主表和子表形成两个管理入口，违反父子结构只在表格管理的产品决定。
- 将换父拆成删除旧边再创建新边：拒绝。会暴露临时独立状态，并改变已有原子换父及单条 Activity 的语义。
- 删除四类普通关系的后端接口和历史数据：拒绝。本次范围是下线 Web 入口；删除服务端事实会造成破坏性兼容变化和历史信息损失。
- 使用工作项 ETag 解除或更换父项：拒绝。父子关系不修改工作项版本，必须使用关系聚合自己的版本防止覆盖并发修改。

## Consequences

Web 用户通过表格管理父子结构，详情抽屉不再提供普通关系编辑。历史普通关系仍可通过 API 读取并在动态中展示，本次没有数据库或 API 契约变更。未来重新开放相关、阻塞、来源或重复操作时，需要明确新的产品入口并继续复用双侧授权、关系 ETag 与原子命令，不能仅重新挂载已下线的关系页。
