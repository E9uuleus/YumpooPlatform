# Agent Note: 工作项搜索与筛选覆盖子项

Status: implemented

## Problem

项目表格只请求主行，搜索与筛选也只判断主行本身：按名称或编号找子工作项得到空表；父项进行中、子项已完成时筛选「已完成」看不到该子项；展开父项后子项表也不过滤。分组请求把表段值与用户筛选写进同一组参数求交集，无法区分「主行属于哪一组」与「谁命中了筛选」。

## Decision

TABLE 列表的主行在本身或任一未删除、未归档的直接子项满足全部匹配条件时返回。匹配条件是 q、状态、优先级、处理人、类别、截止日期、更新时间、计时与连接；只约束主行本身的条件是 assigneeSetUserId、emptyField 和新增的 groupStatus、groupPriority、groupContentId、groupDueFrom、groupDueTo。仓储以 Rows（ITEMS、ROOTS、ROOTS_OR_MATCHING_CHILD）区分三种范围，子项命中用「本身匹配的工作项」子查询表达，谓词文本复用一份。KANBAN 与按类别列表保持只看卡片本身。

列表项返回 `matchedSubitemCount`。子项接口接受同一组匹配条件，只返回命中的子项。Web 在 URL 中有搜索或字段筛选时，展开 `matchedSubitemCount > 0` 的主行，期间的手动展开收起只存内存，筛选变化清空，不改本机展开记录；分组隐藏空组。分组表段请求改用 group* 参数，归属与表段数量按主行本身的字段值。筛选弹窗的数量用 `countSubitems=true` 按工作项本身计数，主行与子项各计一次。

「隐藏已完成 → 不显示」的隐式状态条件也按主行或子项命中，已完成但仍有未完成子项的父项继续显示；子项请求只带用户设置的条件，不带隐式状态条件。

## Alternatives considered

- 前端对已加载的子项过滤：子项按需加载，未展开的父项无从判断，分页后的结果不完整。
- 筛选时展开所有有子项的父项并逐个请求子项：每页最多 25 次额外请求，未命中的父项还会显示空子表。
- 分组请求继续与筛选求交集：子项命中的父项会落入子项字段值的分组，或在两个分组中重复出现。
- 看板也按子项命中：父项会出现在子项状态的泳道里，拖动语义随之混乱。
- 筛选弹窗沿用主行计数：父项进行中、子项已完成时「已完成」显示 0，与点选后的结果矛盾。

## Consequences

[字段分组](2026-09-14-work-item-field-grouping.md)的表段条件不再与筛选求交集；[隐藏已完成](2026-10-19-work-item-hide-completed.md)的「不显示」会保留仍有未完成子项的已完成父项。命中子项计数多一次按页的聚合查询；带筛选的主行查询多一层子项子查询，未带筛选时 SQL 与原来相同。筛选期间新建的子项若不满足条件，刷新后不在子表中出现。
