# Agent Note: 多项并行计时、均摊计入、父项汇总与我的一天补录

Status: implemented

## Problem

同一父项下联系紧密的子项需要同时推进，无关工作项也可能并行进行；单人单计时只能让用户反复切换。补录遗漏时段时，跨项目重叠校验会拒绝记录，但用户看不到该时段已有的工作。下班后集中补录同样被重叠限制阻挡，而且缺少按天核对和补录的入口。

根因是一条计时记录同时承担“什么时候在工作”和“在做哪个工作项”两层含义。此前通过禁止本人记录重叠控制日工时总量，无法表达并行工作，也把补录变成了冲突处理。

## Decision

### 会话事实与计入时长

1. `work_item_time_session` 仍记录某人在某工作项上的 UTC 区间。不同工作项允许重叠；同一用户、同一工作项的未删除区间不能重叠，运行中会话最多一个。用户级状态锁串行化写入，活动会话唯一索引的范围改为公司、用户和工作项。
2. 同一人同一时刻有 N 个有效会话时，每个会话计入 1/N。有效会话为未删除且时长大于零的会话，运行中会话保留开放区间；计数跨全部项目，包括已归档项目与已删除工作项上的会话。全量本人有效会话在任一时段的计入合计等于区间并集时长。
3. 会话与摘要的旧字段 `durationMs`、`completedDurationMs`、`totalDurationMs`、`ownDurationMs` 保持原始区间语义。列表时长排序与范围筛选、统计与图表、团队工时表、项目工时日志、`/me/timesheet`、加班、工时异常任务及计时候选的 `ownDurationMs` 使用按并行均摊后的计入时长。统计仍保留各自的项目可见性和 ACTIVE 范围。
4. 父项的单元格、列表时长排序与范围筛选、`timeTrackingState` 筛选使用本项加有效直接子项的汇总；直接子项须有未删除的 `PARENT_CHILD` 关系且工作项未删除。`allocatedDurationMs` 为本项计入时长，`rollupDurationMs` 为汇总，`rollupRunningRate` 表示每毫秒的增长量。其余统计均不汇总父项，避免子项重复累计。父项日志可通过 `includeChildren` 带出直接子项记录并标注来源；编辑、删除仍使用记录自身的工作项，清除只作用于本项记录。父子关系创建、换父、解除以及工作项删除、恢复推进项目计时修订号，使相关排序游标失效。
5. `start` 把目标加入运行集合，已运行的目标不重复写入；`switch` 停止目标以外的全部运行会话后开始目标；`stop` 只停止指定会话；`stop-all` 停止全部。并行数量不设上限，批量 start 请求仍受每次最多 10 项的契约约束。
6. REPLACE 仅裁剪本人已停止、未删除且所在项目可见、ACTIVE、非 `COMPANY_ADMIN_READ_ONLY`，工作项未删除且未归档的会话。其他会话原样保留，新补录与之并行。归档项目会话也参与并行分母，后续补录可改变其计入时长；归档项目仍不进入统计。
7. 写路径沿用项目锁按 UUID 排序、`work_item_timer_state FOR UPDATE`、工作项锁按 UUID 排序的顺序，再写会话、重建分摊、推进修订号。用户所有会话写入与分摊重建在该用户状态锁内、同一事务完成。
8. 本次写了会话的项目通过 `advanceProjects` 使用 INSERT … ON CONFLICT 推进计时修订号；仅分摊变化的其他项目通过 `touchProjects` 只 UPDATE 既有修订行，不创建新行。两类项目的并集按 UUID 统一排序，再逐项选择对应写法。计时命令推进用户状态版本；补录不推进该版本。

`work_item_time_share` 保存会话按边界切分后的区段、并行数和所属用户、项目、工作项，开放段的 `stopped_at` 为 null。旧数据由此前不重叠的约束保证可按 concurrency=1 回填。读取以区段时长除以 concurrency，聚合后向下取整到毫秒；会话同时返回计入时长及期间并行的其他工作项数。

每次写入只重建受影响窗口。窗口边界吸附到已有分摊段的起止点，删除窗口内旧行，再用所有相交有效会话的切点重新分段；重建前后的项目并集用于修订号更新。启停、切换、全部停止与归档停止使用同一个写入时刻作为 `[now, null)` 起点；新增、删除、编辑、fill 和项目清除使用受影响区间或其外包区间。项目归档停止该项目内每个用户的全部运行会话并重建分摊；永久清除枚举该项目全部会话的所属用户，在各自状态锁内按既有批次预算删除会话并为剩余会话重建分摊。两条多用户路径都在本批用户处理完成后统一更新项目修订号。分摊行随会话外键级联删除，全局 `timer_state` 行保留，不随项目清除删除。

实现沿用执行方案，并依据审查与架构门禁作了以下最小适配：

- 修订号按两类项目并集全局排序，并在归档、清除的用户循环结束后更新。分组排序会让不同用户按相反顺序锁住项目修订行；循环内更新则会在持有修订锁后等待下一用户状态锁，两者都可能死锁。
- 项目清除保留用户状态行，全部会话删除均走用户锁。原先先删独占用户状态、仅重建已共享用户的做法，会在批次之间失去稳定锁行；用户随后向其他项目并行补录时，普通删除可能漏掉重新分摊。保留只含公司、用户与版本号的状态行关闭该窗口，也避免等待状态锁的写者在行被删除后取得空结果；不增加另一套锁协议。
- fill 的重建窗口包含全部被裁剪旧会话与新片段的外包区间。REPLACE 拆分会话后，仅重建请求条目的外包区间会让边界切点外的旧 session 分摊残留，因此不能只使用条目范围。
- Web 的 `startMany` 对超过 10 项的 `resumeItems` 按每批最多 10 项顺序提交，每批成功后用响应刷新状态与 ETag，再提交下一批；失败即停止后续批次。恢复整组因此遵守单次 start 的契约上限，运行集合仍不设总数上限。
- `mySessions` 仓储查询会话时只关联工作项与内容表，不直接 JOIN catalog 项目表。应用服务先通过 `findVisible` 确认可见项目，再用现有 `ProjectConnectionTargetQuery` 按已授权 IDs 批量查询项目名称，遵守模块数据库边界，不新增接口抽象。

### 本人时间段查询与补录

`GET /me/time-sessions` 返回本人指定时段的会话，单次范围最多 7 天；不可见项目的标题、编号、项目名和颜色为空，记录可编辑性沿用项目及会话权限。`POST /me/time-sessions/fill` 使用 XSRF 与幂等键，不要求 If-Match；同一工作项的条目先求并集，运行中会话按无限延伸处理。

- PARALLEL：只补目标工作项在所选区间内尚无本人会话的部分，与其他项并行。
- REPLACE：先在条目区间并集内删除、缩短或拆分可裁剪的其他工作项会话，再补目标工作项的空白。不可裁剪会话保留，拆分右段作为 MANUAL 会话。
- GAPS：只补本人全部会话均未覆盖的区间。

新建、缩短和删除继续发布已有 added、edited、deleted 事件，不新增事件类型或版本；返回创建、修改、删除数量和跳过时长。旧的单工作项补录接口保留，同项重叠仍拒绝，Web 新增记录统一使用 fill，编辑继续使用 PATCH。

“我的一天”的页面形态、拖选补录、重叠处理默认值、按时长排入和拖动调整已由[我的一天时间线填报](../product/2026-10-15-my-day-timeline-and-timer-opt-out.md)取代：原抽屉、三选一补录方式和按时长补录对话框已删除。上述 fill 三种模式、20 条 entries 上限和补录不推进计时状态版本的约束不变。

### Web 与桌面命令映射

Web 以 `runningSessions` 展示运行集合，单项按钮仅停止该项；全局时长取最早运行开始时刻，聚合标题使用“首项 等 N 项”。全部暂停后，“继续”使用最近一次同时停止的 `resumeItems` 恢复上一组；只有单项时沿用最近工作项。候选排除所有运行项，选择即并行开始，“只计时此项”显式执行 switch。

桌面主进程、preload 契约和 IPC 白名单保持现状。Web 将运行集合首项的 sessionId/workItemId、聚合标题和最早开始时间映射到旧桌面状态；recent 使用 resumeItems 首项并在多项时聚合标题。旧 `stop` 命令在 Web 执行 stop-all；旧 `start` 的 workItemId 属于 resumeItems 时恢复整组，否则只开始该项。悬浮球、侧边栏和托盘因此显示聚合状态，暂停等于全部暂停，继续恢复上一组。

## Alternatives considered

- 单计时配合快速切换：仍无法表达同时推进的工作，也不能消除补录重叠冲突。
- 并行各项均计全额：会使个人日合计超过实际时长，统计失去统一口径。
- 手动指定分摊比例：增加输入和校验负担，当前选择自动均摊，不引入比例或权重。
- 读取时实时计算分摊：每个列表、统计、日报与日志都需处理区间切分，SQL 复杂且易出现不同口径，因此写入时维护共享分摊事实。
- 只记录没有时段的日工时：不能核对该时段已有工作，也无法按重叠区间统一分摊。
- 在报表中累计父项汇总：父项与子项同时进入全事项统计时会重复累计；汇总仅用于父项显示、列表筛选排序与日志查看。

## Consequences

写入增加了受影响窗口的分摊重建成本，并可能推进其他项目已有的计时修订号。REPLACE 裁剪长会话时，重建范围可超出本次补录条目。项目清除继续遵守既有批次预算；没有剩余会话的用户状态行也保留，不保留已清除项目的内容。

归档项目内容保持只读，但其既有会话的计入时长可能因后续并行补录而变化；这是全量本人会话统一分母的结果，归档项目仍不进入统计。旧时长字段保持原始区间口径，使用方须选择计入字段或汇总字段，不能将父项显示相加作为报表总量。

发布顺序为后端、Web；桌面端不需要更新。原始会话与 `TimeTrackingRecordQuery` 的职责不变，没有新增事件类型、事件版本、手动比例或并行数上限。之后的[计时器开关与上班时间](../product/2026-10-15-my-day-timeline-and-timer-opt-out.md)增加了个人上班时间、计时器开关和对应的桌面状态字段。
