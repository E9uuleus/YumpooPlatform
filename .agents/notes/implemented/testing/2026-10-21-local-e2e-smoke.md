# Agent Note: 使用系统浏览器的本地端到端冒烟

Status: implemented

## Problem

单元测试、HTTP 冒烟与构建检查不能直接证明浏览器中的导航、项目创建和详情入口可以完成主流程。需要一套可重复执行的轻量检查，同时避免把浏览器环境引入现有合并门禁。

## Decision

`pnpm test:e2e` 运行六个串行 Playwright 用例，覆盖首页登录、创建项目、创建工作项并打开详情、我的一天、收件箱与管理后台。浏览器冒烟只作为本地命令，不属于 CI 或合并门禁。用例上限为 8 个，只覆盖主流程能打开、能保存，不承担控件细节和完整业务回归。

Windows 默认使用系统 Edge，其他系统默认 Chrome；通过 `YUMPOO_E2E_BROWSER` 选择已安装的浏览器 channel，不下载浏览器二进制。依赖固定为发布满 14 天以上的稳定版本。每个用例收集 pageerror、console error 与 API 5xx，任意一项均使测试失败；失败保留截图与 trace。

默认运行构建 Web，使用独立 PostgreSQL 容器和干净环境变量启动本地身份后端，再启动 preview。构建与测试命令异步执行，正常结束、失败或收到 SIGINT / SIGTERM 时，清理本次拥有的进程树与容器；Unix 子进程使用独立进程组，Windows 使用 taskkill 结束进程树。日志和报告保留在 `out/e2e/`。`--skip-web-build` 只跳过构建。设置 `YUMPOO_E2E_BASE_URL` 时复用现有测试环境，跳过服务启动与清理，用例创建的数据留在该环境。

## Alternatives considered

- 立即纳入 CI：会引入浏览器安装、运行环境和失败分诊义务；本次只建立本地入口，将来纳入 CI 必须另作决策。
- 下载 Playwright 配套浏览器：版本一致性更强，但增加下载与二进制维护；本方案使用系统浏览器 channel。
- 扩展为全面 UI 回归：维护成本超出冒烟目标；保留最多 8 个主流程用例，细节仍由现有测试负责。

## Consequences

运行者需要 Docker、Java 21、已构建的 JAR 和系统浏览器。默认模式每次创建独立数据库，重复运行不依赖前次数据；指定现有环境时需要接受测试数据写入。自动化等待使用页面状态、定位器和服务就绪探针，不使用固定 UI 等待。

页面引导通过现有关闭入口处理，选择器使用现有可访问名称与页面标识，不为测试修改 Web 生产代码。报告仅证明这六条主流程，不替代完整业务、安全、桌面安装更新与生产部署验证。

Windows 系统 Edge 实测：完整构建后 6/6 通过，随后 `--skip-web-build` 再次 6/6 通过；结束后测试容器为空，8100 和 18174 均可重新监听。本机 JDK 21.0.6 在默认临时目录创建内部 socket 失败，验证 shell 将已有的 `TEMP/TMP` 指向仓库内临时目录后正常启动，后端环境仍只继承计划中的系统变量。
