# Agent Note: Agent 执行与交付范围

Status: implemented

## Problem

通用执行规则散落在个人配置、项目 AGENTS.md 和 Skills 中时，阶段确认、清理批准和完成条件容易发生分叉。项目原有的分支与 PR 条款没有区分本地审阅修订和要求集成的开发任务，提交格式又无条件要求步骤编号，容易给普通修订附加无关流程。

## Decision

项目 AGENTS.md 只补充仓库事实和项目约束。自主执行、信息澄清、批准复用以及任务完成的通用语义由当前生效的全局 AGENTS.md 维护，Skills 提供与所选任务有关的领域约束。请求是否包含提交、PR、合并或部署决定需要达到的交付阶段；本地审阅与修订不自动扩展为发布。

需要产生仓库提交的独立变更基于最新 dev 使用独立分支；集成必须通过目标为 dev 的 PR，禁止直接推送 dev，合并前必须通过代码审查和 CI。分支名前缀遵循当前平台默认或用户指定，不再把示例 feature 前缀当成唯一允许值。

提交消息继续使用 type(scope) 和简洁中文说明。仅当任务已有步骤编号时附加编号，避免人为制造步骤；有多个子功能时用正文分段说明。docs/ 仍不跟踪、不提交、不推送。

Agent Note 的写入门槛、生命周期与冻结档案规则继续由[治理契约](../../README.md)及[治理决策](2026-08-20-agent-notes-governance.md)维护。本记录只解释执行范围与 Git 交付条款，不复制个人 Skills 的完整行为规则。

## Alternatives considered

- 为每个 Skill 复制自主性和批准规则：短期明确，但会再次产生多处维护和冲突，因此通用语义保留在全局入口。
- 对所有本地修订都立即创建 PR、合并和部署：可统一流程，却把审阅任务扩展为用户未要求的集成与发布，因此按实际交付范围选择终态。
- 删除项目的 Git 与审查约束：减少步骤，但破坏协作质量要求，因此保留独立分支、dev PR、代码审查和 CI 门禁。
- 无条件保留提交步骤编号：能表达分步实施，但普通修订没有真实编号，因此改为有编号时才附加。

## Consequences

Agent 可以完成授权范围内的本地修订与验证，不需要为进入下一阶段重复索取同一授权。需要集成的工作仍遵循原有审查与 CI 边界。

个人配置不进入仓库，其他协作者使用自己的全局 AGENTS.md；仓库必须独立保留 Git、编码、目录和决策档案等团队约束。此调整改变的是指令与交付范围，不改变产品运行行为。
