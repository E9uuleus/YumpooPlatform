# Agent Note: Agent Notes 单文件治理

Status: implemented

## Problem

代码和普通说明文档适合描述当前行为，却难以长期保存一个跨版本决策为何出现、哪些可信方案被放弃，以及未来在什么条件下可以重新评估。缺少统一约束时，决策记录容易散落、重复、失去实现同步，历史记录也可能在普通文档整理中被无意改写。

YumpooPlatform 需要一套仓库级治理机制：既让仍有决策价值的记录保持可发现，又避免把每次非平凡修改都转化为文档负担；同时，目录结构、文件格式和冻结历史必须能够由只读工具稳定验证。

## Decision

Agent Notes 已作为长期决策记录落地在 `.agents/notes/`。活动记录使用 `proposed`、`implemented`、`rejected` 三个封闭 lifecycle；`archived` 是独立的冻结历史区，不属于活动 lifecycle。合法迁移仅为提案落地、提案拒绝、已实施记录归档，以及失去防错价值的拒绝记录删除。

记录按 `architecture`、`product`、`data`、`security`、`process`、`testing` 六个封闭 class 分类。每条记录只使用一个 UTF-8 Markdown 文件，路径中的日期和 ASCII kebab-case 主题共同形成稳定身份；生命周期迁移不改变该身份。

只有建立、修改或推翻长期且可能被后续维护者重新讨论的决策时，作者与评审才要求新增或更新记录。局部缺陷修复、内部重构、常规测试和机械修改通常不需要记录。已有记录拥有该决策时更新原记录，避免重复 owner。完整替代发生前，新 owner 必须吸收旧记录的独特理由、替代方案和约束；旧 implemented 记录随后进入冻结区，而不是被删除。

机器门禁使用共享的 lifecycle、class 和目录允许列表，校验活动记录的路径、身份唯一性、编码、标题、状态及必需章节；implemented 正文不得保留提案期章节。Markdown 链接检查覆盖当前治理文档和活动记录，但不把冻结记录正文当作当前规范来源。门禁只验证已经存在的记录，不从代码差异推断是否应写记录；写入门槛仍由作者和评审进行语义判断。

归档采用版本化、仅追加的 SHA-256 manifest。归档文件保留 `Status: implemented`，增加合法归档日期，并以原始字节计算摘要。只读校验器将当前 manifest 和文件与可信 Git baseline 比较，拒绝删除、移动、内容变更、旧摘要改写或未封存的新文件；写入模式只能在旧封印全部有效时追加新摘要。CI 在拉取完整历史后运行链接、活动记录、冻结归档和对应测试，并把 PR 基线或推送前提交传给归档校验器。

## Alternatives considered

- 要求所有非平凡变更都写记录：覆盖面更广，但会制造大量低价值记录，稀释真正需要长期维护的决策，因此改用语义门槛。
- 由 CI 根据代码差异判断是否缺少记录：自动化看似严格，但无法可靠理解决策范围和既有 owner，因此 CI 只验证已有记录的结构与冻结完整性。
- 为每条记录维护多语言文件及配对元数据：会同时引入同步协议、写入工具和额外校验成本；本项目当前没有对应需求，因此采用单文件模式。
- 把归档视为普通文档并允许持续修订：有利于统一术语，却会削弱历史证据的可信度，因此归档一经封存便冻结原始字节。
- 仅信任当前工作树中的 manifest：攻击者可同时修改正文和摘要而绕过检查，因此必须对比可信 Git baseline，并禁止改写旧条目。
- 预先创建所有 class 目录或维护集中索引：会留下空目录占位或产生第二份目录真相，因此 class 按需创建，并由文件树和机器门禁提供发现能力。

## Verification

`pnpm run doc-sync` 已验证全部本地 Markdown 链接、活动记录结构和冻结归档状态。Agent Notes 的 Vitest 套件已覆盖合法正例、目录和格式错误、重复身份、编码与换行错误、链接目标和锚点、归档追加、可信 baseline、内容删除或篡改、路径移动及 manifest 改写。归档技能也已通过仓库技能格式校验。

## Coverage gaps

机器门禁有意不判断一项代码变更是否达到 Agent Note 写入门槛，也不判断正文理由的充分性；这些仍是作者和评审的语义责任。当前冻结区没有历史 Note，真实仓库中的首个封存操作尚无长期运行样本，但临时 Git 仓库测试已经覆盖首次封存和后续不可变约束。

## Consequences

长期决策现在有稳定的生命周期、分类和格式，活动记录能与实现保持同步，冻结历史能作为不可变证据保留。新记录和迁移需要作者主动搜索同主题 owner、说明替代方案，并在完整替代时保全旧记录的独特信息。

该制度增加了文档评审、链接维护、测试执行和归档封存成本。六个 class 和三个活动 lifecycle 是封闭集合，新增分类或迁移必须先修改治理决策、共享规则、文档和测试。冻结记录不能通过日常整理修复；若历史术语过时，当前文档必须在活动区说明，而不能改写已封存内容。
