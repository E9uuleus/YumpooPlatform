# Agent Note: 事件契约显式退役与只追加记录

Status: implemented

## Problem

兼容门禁默认禁止既有事件缺失，无法表达已批准删除一个业务聚合的决定。直接删除比较逻辑会掩盖意外断约；只移除事件目录而留下 schema 或样例，会使可发现的合同与实际生产者矛盾。

## Decision

[退役清单](../../../../tools/events/retired-event-contracts.json) 以 schemaVersion 1 和 retired 数组登记 eventType、eventVersion、非空理由与实施决定路径。路径允许 implemented 或 archived；implemented 原文件不存在时，只接受 archived 下同分类同名的文件，不修改清单中的原路径，不搜索其他分类或近似名称。归档文件只承载原始退役授权，当前实现仍以活动决定和代码为准。类型和版本构成唯一键。历史政策只允许在数组末尾追加，既有条目不得修改、删除或重排；没有该文件的旧 Git 基线视为空清单。

比较基线时仅跳过已登记的确切类型和版本，未登记的缺失仍然失败。退役事件不得存在于当前 catalog、schema 或合法/非法样例，也不得属于任何 freeze 清单。当前文件扫描与基线路径检查共同避免遗留文件被目录移除掩盖。同时递归扫描 backend/src/main/java 下全部 Java 文件，仅在当前目录中已无任何版本时拒绝退役事件类型的完整字符串字面量，并报告文件及行号；生产者、订阅和共享常量均受约束。扫描根目录缺失即失败，测试夹具与历史 SQL 不参加生产源码扫描。该检查按类型字面量阻止重新引入，不解析动态拼接或推断运行时事件版本；仍有有效版本的类型允许继续生产和订阅，其版本由当前契约、消费者清单及测试约束。事件信封、共享 payload、未退役事件的字段兼容及冻结消费者语义继续按原门禁验证。

首次使用由[删除产品决定](../product/2026-09-30-remove-product-concept.md)拥有，退役八类 catalog 产品及关系 v1 事件。已保存的安全审计与冻结历史不因此获得改写授权；数据库清理由该业务决定与追加迁移明确限定。

[统一项目模型](../product/2026-09-30-unified-project-model.md)退役 project_created@1 并发布 @2，因此同一类型字面量仍可使用；最后一个有效版本也退役后恢复类型级禁令。两种场景均有兼容门禁测试。

`YumpooServerApplicationIT.registeredOutboxSubscriptionsMatchCurrentContractsAndExcludeRetiredVersions` 从实际应用上下文枚举全部 `OutboxEventConsumer` 的订阅，每个类型与版本必须存在于当前 catalog，且不得出现在退役清单。该运行时回归补足类型字面量扫描的版本边界，防止有效类型继续订阅已退役的旧版本。



## Alternatives considered

- 给所有 catalog 事件或所有缺失事件豁免：会掩盖与本次业务删除无关的断约，拒绝。
- 修改冻结清单来允许退役：破坏冻结消费者的稳定合同与通知边界，拒绝；冻结事件不能通过本机制退役。
- 保留 schema 或空生产者作为兼容占位：会继续宣传已不存在的业务能力，也不能解释存量数据处理，拒绝。
- 反复修改一条退役记录表达新版本：失去原始授权依据；每个类型和版本必须独立追加。
- Note 归档时改写既有退役路径或永久禁止归档：分别破坏只追加记录或正常 Note 生命周期；按同分类同名归档路径解析即可保持两者。
- 只检查事件目录而不检查后端源码：无法发现重新引入的生产者或订阅，会产生缺少当前契约的事件；源码检查与契约检查共同执行。
- 改写历史证据、维持失效的源码片段门禁或跳过当前回归：分别破坏历史可信性、阻止合法删除或失去当前行为保证，拒绝。

## Consequences

退役与 schema、样例删除必须同一变更交付，并提供可追溯的实施决定。以后仍要恢复同名同版本事件时，不能修改或撤回旧退役条目，应先评审新版本契约及生产与消费迁移责任。类型级源码禁令仅适用于全部版本退役。OpenAPI 删除仍独立遵循精确 SHA-256 例外，事件退役不会放宽 HTTP 兼容检查。

测试覆盖已登记退役、未登记缺失、冻结事件禁止退役、当前目录与遗留文件拒绝、退役记录改写/删除/重排，以及 Note 正常归档不改清单、归档错位或缺失、生产者/订阅/常量重现、扫描范围和根目录缺失。里程碑脚本与历史 evidence 校验已退役，历史记录由 Git 保留。当前生产者、Activity 订阅和冻结事件盘点继续参加完整 CI。
