# Agent Note: 事件契约显式退役与只追加记录

Status: implemented

## Problem

兼容门禁默认禁止既有事件缺失，无法表达已批准删除一个业务聚合的决定。直接删除比较逻辑会掩盖意外断约；只移除事件目录而留下 schema 或样例，会使可发现的合同与实际生产者矛盾。

## Decision

[退役清单](../../../../tools/events/retired-event-contracts.json) 以 schemaVersion 1 和 retired 数组登记 eventType、eventVersion、非空理由与活动实施决定路径。类型和版本构成唯一键。历史政策只允许在数组末尾追加，既有条目不得修改、删除或重排；没有该文件的旧 Git 基线视为空清单。

比较基线时仅跳过已登记的确切类型和版本，未登记的缺失仍然失败。退役事件不得存在于当前 catalog、schema 或合法/非法样例，也不得属于任何 freeze 清单。当前文件扫描与基线路径检查共同避免遗留文件被目录移除掩盖。事件信封、共享 payload、未退役事件的字段兼容及冻结消费者语义继续按原门禁验证。

首次使用由[删除产品决定](../product/2026-09-30-remove-product-concept.md)拥有，退役八类 catalog 产品及关系 v1 事件。已保存的安全审计与冻结历史不因此获得改写授权；数据库清理由该业务决定与追加迁移明确限定。

产品删除令 M2-03、M2-07、M2-24 的实现片段检查失效，沿用类别重构先例纳入 [historical-assets](../../../../tools/ci/historical-assets.mjs)。M2-03/07 要求历史 PASS；M2-24 保留原报告 VERIFIED、V45 和全部成功检查的语义。历史报告与非空验收矩阵只证明当时验收，当前行为继续由契约、迁移、后端全量回归和前端测试负责。历史 evidence 不修改；未受影响的当前资产门禁保留。

## Alternatives considered

- 给所有 catalog 事件或所有缺失事件豁免：会掩盖与本次业务删除无关的断约，拒绝。
- 修改冻结清单来允许退役：破坏冻结消费者的稳定合同与通知边界，拒绝；冻结事件不能通过本机制退役。
- 保留 schema 或空生产者作为兼容占位：会继续宣传已不存在的业务能力，也不能解释存量数据处理，拒绝。
- 反复修改一条退役记录表达新版本：失去原始授权依据；每个类型和版本必须独立追加。
- 改写历史证据、维持失效的源码片段门禁或跳过当前回归：分别破坏历史可信性、阻止合法删除或失去当前行为保证，拒绝。

## Consequences

退役与 schema、样例删除必须同一变更交付，并提供可追溯的实施决定。以后仍要恢复同名同版本事件时，不能修改或撤回旧退役条目，应先评审新版本契约与迁移责任。OpenAPI 删除仍独立遵循精确 SHA-256 例外，事件退役不会放宽 HTTP 兼容检查。

测试覆盖已登记退役、未登记缺失、冻结事件禁止退役、当前目录与遗留文件拒绝、退役记录改写/删除/重排，以及历史验收状态、失败检查和空矩阵的拒绝路径。当前生产者、Activity 订阅和冻结事件盘点继续参加完整 CI。
